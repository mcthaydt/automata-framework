## Findings that shape the design

- **The framework already writes the page.** `docs/stack.md` is generated by `pnpm docs:stack` (PRODUCT.4) from the version pins, the installed packages' licences and hand-written cards, and the framework's own `pnpm check` fails when it is stale. The site must not rewrite it, so there is no second source of the words, the versions or the licences.
- **The copy is held to a commit, not to a moving `main`.** `pnpm sync:stack` copies the file from the sibling checkout's `origin/main` and records the last commit that changed it and its sha256 (`src/data/stack.source.json`). `tests/stack-page.test.ts` checks the sha256 and that the copy equals `git show <commit>:docs/stack.md`. CI's framework checkout is pinned to `framework.ref` (`365f115`, before the page existed) but fetches full history, so the recorded commit, which is on `main`, is there to compare with. `pnpm sync:stack --check` says whether the framework has moved the page since; it is a manual check, not a CI gate, because a CI that follows `main` would go red for reasons unrelated to the change under test (the QB.3f finding).
- **The page is shown unchanged, apart from two mechanical edits.** The generated-file comment is dropped (the page shows its own heading), and the one relative link (`versions.md`, a framework file the site does not serve) points to that file on GitHub. Anything the page cannot lay out (a code block, a quote, a heading below level 2, a numbered list) makes `stackSections` throw, so a new kind of block in the framework fails a test instead of appearing as raw text.
- **Bold is new to the site's inline text.** The page uses `**Core**` and `**Plus**`; `parseInline` now reads `**…**` as strong text, never inside a code span.
- **Tables scroll, they do not shrink.** Each table sits in a keyboard-focusable, labelled scroll region, as on `/docs` and `/cheatsheet`; the overview table has the page's anchors to each library's section.
