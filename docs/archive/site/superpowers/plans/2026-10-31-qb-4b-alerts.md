# QB.4b: deploy hardening, uptime, certificate expiry and spend alerts (plan)

> **Row:** framework `docs/02-master-delivery-plan.md`, QB.4b (prerequisite DX.12, merged). **Lane:** website.
> **Branch:** `claude/website-QB.4b-alerts`.

## Goal

An external uptime and certificate-expiry check, and a spend alert on the site host (later the Plus store and the GPU
runner). The site has never been deployed, and deploys stay dry runs until the project is complete. The monitor account,
its alert recipient and the billing alert belong to the Owner. So this task delivers the check itself, testable today,
and the runbook that says what each alert watches, its threshold and who sets it up. Nothing is scheduled against a
host that does not exist.

## Interfaces produced

| Name | File | Notes |
| --- | --- | --- |
| `certificateProblems(validTo, now, minDays)` → problems | `scripts/check-uptime.ts` | a problem when the certificate has expired or has fewer than `minDays` days left |
| `checkUptime(origin, options)` → problems | `scripts/check-uptime.ts` | `/` answers 200 within the timeout; for `https:` the served certificate passes `certificateProblems`; a plain `http:` origin is a problem unless `allowHttp` |
| `peerCertificate(origin)` → `{ validTo }` | `scripts/check-uptime.ts` | one TLS handshake, the leaf certificate's expiry |
| `pnpm check:uptime <origin> [--min-cert-days 21]` / `--local [--build build]` | `scripts/check-uptime.ts` | `--local` serves the build with `serve-static.ts` and checks status only, saying the certificate was not checked |
| `docs/operations/alerts.md` | | the three alerts, thresholds, recipients, the Owner's steps |
