# c9-wardrobe Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hosiery, boots, soft caps, a tabard, pleats and gathers, rolled sleeves, front-falling hair and a bob, tiny
text and marks, and four more drawn faces, each a generator plus data any character can use; registered and shown in
automata-framework; Ada and the Nurse re-rendered with them.

**Architecture:** FigureBuilder (FB) gains generic, off-by-default machinery (a sheer material's edge, the shod foot's
form, the foot's measures, hair fields and a fringe piece, glyphs, drawn moods). automata-framework's (AF) character
kit gains the garment kinds through H1, beside the runway's nine, and passes expressions to the painter. The showcase
branch takes a scripted copy of the kit's kinds.

**Tech Stack:** FB: TypeScript, vitest, vite-node, `@napi-rs/canvas` (scripts only). AF: pnpm workspace, vitest,
Playwright, zod. No new dependency in either.

**Spec:** `docs/superpowers/specs/2026-11-11-c9-wardrobe-design.md` (read it first; section numbers below are its).

## Global Constraints

- CLAUDE.md's rules hold in FB: the layer order, DUEL colours only, whole steps along a ramp, never reorder a figure's
  parts, never cut hook machinery as dead, no per-character code, no hand-drawn pixels, never nudity, no costume or
  stereotype. AF's `AGENTS.md` holds in AF: test first, the door is the only importer of `figure-builder`, a source file
  has at most 600 lines, `pnpm format` and `pnpm check` before a commit, Conventional Commits, a `patch` changeset.
- **No FB golden moves.** `tests/golden/{base,lit,actors,sprites,sprite}*` has no file in any diff. A red golden means the
  change is wrong. `tests/golden/wardrobe.json` is new (Task F9).
- **No AF golden moves:** the runway golden (`tests/fixtures/runway-golden.ts`) and the showcase cells, across the
  submodule bump and every kit change. A moved cell is investigated, never re-recorded.
- **Off by default.** Every new field or name left out gives today's code path and today's texels. Each FB task's test
  asserts it against a cell drawn before the change (Task F0's pins).
- **Additive contract.** `STAGE_VERSION` stays 1 and the package 0.2.0. Each task that adds a name to `src/index.ts` or
  `src/kit.ts` adds it to `tests/api.test.ts` in the same commit; Task F9 writes the changelog.
- `hair/hair.ts` is 597 lines and `paint/paint.ts` 1588: new hair code goes in new files beside it where a closure of
  `hairParts` is not needed; follow the file's own style (dense, commented by why).
- Before each FB commit: `npm run typecheck` and `npm test`. After a painter change (F1, F8): `npm run view-check`.
- No subagents are required by the plan. Commit after every task with the message given.
- **The grain** (audit B1). A figure's parts are `[...body(), ...garment and hair parts]` (`dress()`), and the part index
  seeds the grain, so a part inserted anywhere but the end of that whole list moves the grain of every part after it.
  Every new part c9 adds to FB (the shaft, the heel's ball, the toe cap) is appended to the end of `dress()`'s `all`, never
  inside `body()`'s per-side loop; a part that replaces one (the sole as the heel block) keeps its index.
- **Arch-stable** (audit B4). AF's `checks` job runs on the arm64 Mac (`af-mac`), and P1 and P2 compare md5s FB recorded on
  Linux. Every new frame of `wardrobe.json` passes a nudge test (`tests/support/ulp.ts` `nudged`, as
  `tests/features/hair/ulp.test.ts` does); a new hair path with a pole takes `grid()`'s rule (a pole faces the way its row does).
- **Fixture kinds** (audit S3). FB has no way to unregister a garment kind; vitest isolates test files, so a fixture kind
  is registered once per file, guarded (as `paint/fabric-fixtures.ts` guards its fabrics), and carries what varies in its item.

## Review Focus

Inputs the spec implies and a person would meet; each has its test in the task named.

1. **A slider at its end under a new piece** (fat 1 under a knee boot, a thick neck under a long front fall, a small head
   under a cap): it must clear the body, never clip. Tests in F2, F4, F6, A3.
2. **Two garments that set the same thing** (boots and shoes both set `Fit.shoe`; trousers over a shaft; a tabard over a
   coat): the last wins or the outer clears, never z-fighting texels. Tests in F2, A3.
3. **Text the font lacks or that is too long** (`é`, a 20-letter name, an empty string): `lettering` throws with the
   character named; `fitText` falls back; an empty text gives a blank plate. Test in F7.
4. **An expression with a blink, with `talk`, with a gaze tag, in profile and from behind**: no mark off the face, none
   on hair or a cap. Test in F8.
5. **A second `registerFashion()` call and an unknown expression name from a game**: the first is a no-op, the second
   throws in words naming the list. Tests in A3, A4.
