## Decisions made here (defaults, for the Owner's veto)

1. **`'policy'` joins `StorageFailure`**, so a `StorageError` may carry it too (the disk adapter of EDS.1d refusing a read outside its allowlist) and every consumer that passes a failure along (document session, autosave, editor-2d's outcomes) keeps compiling without a mapping. No kit adapter produces it.
2. **`expected: 'absent'` on the download store** is accepted and ignored: the store holds nothing, so every path is absent.
3. **Remove without an open change set is `policy`.** §4.3 ties `remove` to "the journal's record that this change set created the file"; with no change set there is no journal.
4. **`SuiteEditor.icon` is a `string`** (the kit has no icon set yet); `hue` names the `color/ed/*` token.
5. **`AskContext` is plain data** (`Readonly<Record<string, string | number | readonly string[]>>`), as The Last Light's context is a bag of optional strings.
6. **`CheckDef`** is `{ id, when, run, joins, measure }` with `run` the argv (§4.2); the built-in `content` check is the suite's, not the runner's, so `declared()` lists only the game's checks.
7. **A check run never rejects.** An unknown id, a check that throws and a cancelled or replaced check each resolve as `error` with the reason in `output`; a newer run of an id cancels only that id in the older run (§7).
8. **The change set fake** follows The Last Light's `ChangeSets` (`92e6704`, `editor/src/server/changeset.ts`): branches are `edit/<slug>`; `begin` twice or with an unsluggable title rejects; `record`, `checkpoint` and `ship` reject without one; `ship` checkpoints and leaves the change set open; a checkpoint with nothing recorded since the last returns the last commit. The token cap defaults to 200 000, The Last Light's.
9. **Gates:** `states(ids)` answers in request order; an id with no record is `unknown`; unreadable records reject (the pill's "Gates not readable").
