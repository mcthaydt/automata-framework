# c8 Lit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (no
> subagents in this project). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A painted figure in an AF scene is lit by its room on WebGL and WebGPU, hides texel by texel under WebGPU, and
paints the same cell on x64 and arm64.

**Architecture:** FigureBuilder (FB) gains three things: a pole rule in its hair grid (a pinched row's normal faces out
whatever the last bit of `sin` and `cos`), a pure `lightSprite` that lights a painted cell in whole DUEL steps, and a WGSL
stage that writes a depth per texel. AF's character kit reads the room's light
through `SceneLight.tint`, lights each cell on the CPU through FB's function, caches it, and draws it on FB's `CellSprite`
as it draws any cell. Nothing in `packages/3d` changes.

**Tech Stack:** TypeScript; FigureBuilder (git submodule `vendor/FigureBuilder`, `STAGE_VERSION` 1, Vitest 5,
`vite-node`); PixiJS 8.22 with `@pixi/3d` 0.1.0-beta.2; AF's Vitest 5 Node and browser projects; Playwright 1.63.

**Spec:** [`2026-11-11-c8-lit-spec.md`](2026-11-11-c8-lit-spec.md). Read it first: sections 5 to 7 hold the rules and the
evidence this plan argues from. FB's contract is `vendor/FigureBuilder/docs/contract.md`.

## Review Focus

Inputs the spec implies and no happy-path test meets. Each has its test in the task named.

1. **A room with no light at the figure** (`tint` returns 0, 0, 0; a figure outside the level): `flatSteps` clamps to −3,
   no `NaN`, no lamp, the figure is dark, not black and not thrown on. Tasks F2 and A2.
2. **A lamp switched while a figure stands still**: the painted cell's key is unchanged, the light is not; the lit cell
   must change on the next frame. Task A3.
3. **A cell with no normals** (a held item, a flat material; `normals` alpha 0 everywhere) under a strong side lamp: no
   form, no rim from a mean of nothing, no division by zero. Task F2.
4. **The renderer asked for WebGPU and got WebGL** (no adapter): the same lit bytes and per-texel depth as a WebGL
   renderer, no warning. Task A5.
5. **Density or figure size changing under a warm cache** (a view at D1 after D2): a lit cell of the old size is never
   shown. Task A3.
6. **Every figure relights in one frame** (a lamp switched, a flickering lamp's level stepping, the time crossing a
   step): the worst frame of the budget. Task A6.
7. **Daylight with no lamp**: the sun is not in `SceneLight.tint`; the figure still gets the sun's direction. Task A3.

### Task F1: The hair's pole rule

The plan audit found the arm64 flip's owner (spec section 7a, corrected): `grid()` in `src/features/hair/hair.ts` turns a
vertex's normal outward by the sign of `dot(n, p − inner(i))`, and at a pole (a row pinched to a point) `p − inner(i)` is
0 or 1e-10 to 1e-9 m, so the sign is rounding, and a last bit of `sin` or `cos` negates the normal. The raster has no tie
there: positions and depths are bit-identical. `raster.ts` is not changed.

**Files:** modify `src/features/hair/hair.ts` (`grid`); create `tests/support/ulp.ts`, `tests/features/hair/ulp.test.ts`.

**Interfaces:**
- Produces: `nudged<T>(seed: number, run: () => T): T` in `tests/support/ulp.ts`. It replaces `Math.sin`, `cos`, `tan`,
  `atan2`, `atan`, `asin`, `acos`, `exp`, `log`, `log2`, `pow` and `cbrt` for the length of `run`, each returning its true
  value moved one unit in the last place up (a quarter of calls), down (a quarter) or unchanged, by a 32-bit LCG
  (`s = (Math.imul(s, 1664525) + 1013904223) >>> 0`, the top two bits choosing) seeded with `seed`, and restores them in
  a `finally`. Zero and non-finite values pass through. `seed` 0 nudges nothing.
- The rule: `const POLE = 1e-6` (m). Where `|p − inner(i)| < POLE`, the outward direction is the next row's,
  `get(k, j) − inner(k)` with `k = i === 0 ? 1 : i − 1` (the row the function's own `dv` fallback already uses); elsewhere
  it is `p − inner(i)` as today. Fix A of the audit: it paints the Macs' `nia/thin/0` on x64. (Fix B, keeping the cross
  product's sign at a pole, is also stable but leaves a pole facing in where the grid's winding does; it is not taken.)

- Produces, exported from `src/index.ts`:

```ts
export interface SpriteLamp { dir: V3; strength: number }
export interface SpriteStyle { threshold: number; rim: number; rimSide: number; stepRatio: number; down: number; up: number; chroma: number; tint: number }
export const SPRITE_STYLE: SpriteStyle = { threshold: 0.22, rim: 0.35, rimSide: 0.25, stepRatio: 1.17, down: -3, up: 2, chroma: 0.02, tint: 0.35 };
export interface SpriteLighting { flat: V3; lamps: SpriteLamp[]; exposure?: number; style?: SpriteStyle }
/** Whole DUEL steps for a light: clamp(round(ln(peak) / ln(stepRatio)), down, up); `down` for a peak of 0 or less. */
export function flatSteps(flat: V3, style?: SpriteStyle): number;
/** A painted cell lit as a sprite: a new RGBA cell. The spec's section 5a, rules 1 to 8, in that order. */
export function lightSprite(f: LitSource, L: SpriteLighting): Uint8ClampedArray;
```

### Task F4: Per-texel depth under WebGPU

**Files:** modify `src/features/view/cell-sprite.ts`, `src/features/view/stage-view.ts`, `scripts/view-check.ts`;
create `tests/features/view/template.test.ts`.

Read at the plan audit in the installed beta: `MaterialSystemGpu.ensureMaterial` compiles the main pass from
`materialDescriptor.template ?? template`, so a material whose `getPrimaryDescriptor()` returns a `ShaderDescriptor` with
`template` set is the public seam (`ShaderDescriptorOptions.template`). The default WGSL template is the module-internal
`gpuTemplate` in `dist/core/gpu/shader/MaterialSystemGpu.mjs`, whose `mainFragment` returns
`vec4<f32>(finalColor * alpha, alpha)`: FB carries a copy. **The shader cache key is the bit names, never the template**:
the custom template must only ever be used with `cellDepthBit` in the bit list, so its key stays apart from every plain
flat material's.

**Interfaces:**
- Consumes: `@pixi/3d`'s `ShaderBitTemplate`, `FlatMaterial`, `ShaderBit`.
- Produces: `CellSprite(true)` writes a depth per texel under WebGPU; `StageView.perTexelDepth === true` under WebGL and
  WebGPU; `showDepths` keeps its signature. `perTexelDepthWarning` stays for any other renderer type.

  `getPrimaryDescriptor()` returns the parent's bits with `template` set to a copy of `gpuTemplate` whose fragment entry

  struct CellFragment { @location(0) color: vec4<f32>, @builtin(frag_depth) depth: f32 }

  quad with it in front of a blue box: read back the centre pixel. **Blue**: the seam works, go on. **Red**, a WGSL

- [ ] **Step 3: Implement.** The template (a module constant, built once) declares `var cellDepth: f32` before

### Task A3: The room's light for one figure, and the lit cell

**Files:** create `src/features/painted/room-light.ts`, `src/features/painted/lit-cells.ts`,
`tests/unit/painted/room-light.test.ts`, `tests/unit/painted/lit-cells.test.ts`; modify `painter.ts`, `painted-view.ts`.

**Interfaces:**
- Consumes: `SceneLight` (type, from `@automata/3d`: `tint` and `lighting.sun`), `lightSprite`, `flatSteps`, `cellOf`,
  `SpriteLighting`. `tint` is the ambient plus each lamp at its level, with the occluders, capped at 1.6; it has **no sun
  and no fill** and is not stepped (spec section 3, corrected at the plan audit).
- Produces:

```ts
// room-light.ts
export const ROOM_LIGHT = { chest: 1.2, ring: 0.75, hot: 1, floor: 0.05 } as const
/** What `tint` is: the room's light at a point, facing `normal` when given. */
export type Tint = (x: number, y: number, z: number, normal?: readonly [number, number, number]) => readonly [number, number, number]
/** The sun as `SceneLighting.sun` holds it: the direction toward it in the world, its colour (0xRRGGBB) and level. */
export interface Sun { readonly dir: readonly [number, number, number]; readonly color: number; readonly level: number }
export interface RoomLight { readonly lighting: SpriteLighting; readonly key: string }
/** The room's light on a figure whose feet are at `at`, seen from `azimuth` (the painter's view). Pure. */
export function roomLight(tint: Tint, sun: Sun | undefined, at: V3, azimuth: number): RoomLight

// lit-cells.ts
export const LIT_CELLS = 32
export interface LitCells { lit(figure: Figure, light: RoomLight): Cell; readonly size: number }
export function litCells(limit?: number): LitCells
```

  `roomLight`: the flat light is `tint(x, y + chest, z)`; the lean on each axis is the peak channel of `tint` with that
  axis's normal less the peak with its opposite; the resultant, quantised to sixteenths a component after normalising and
  turned by Ry(−azimuth), is one lamp, its strength the resultant's length rounded to 0.1; under `floor` there is no
  lamp. The sun, when given and its `level × peak(colour)` is over `floor`, is a second lamp: `dir` turned by
  Ry(−azimuth) and quantised the same way, strength `level × peak(colour)` rounded to 0.1. It is not occluded (the
  occluder test is not public, and a new export from `@automata/3d` is out of bounds), so a figure in shade by day still
  takes its form: the gate judges it (spec section 11). The flat light and the ring stay `tint`'s, so the exposure
  compares like with like. The fill has no direction and is not used, as `characterTint` does not use it. The ring is
  the mean of `tint(x ± ring, y, z, up)` and `tint(x, y, z ± ring, up)`;
  `exposure = max(0, flatSteps(flat) − flatSteps(ring) − hot)`.

  **The key decides the bytes.** `lighting` is built from the quantised values only: the flat light is
  `colour × 1.17^(flatSteps − exposure)` back out of whole steps, with its colour (the flat light over its peak) in
  sixteenths a channel; each lamp's `dir` in sixteenths and strength in tenths; `exposure` 0 (already taken off). The
  key prints exactly those: `<steps>|<colour r,g,b in sixteenths>|<lamp dir;strength>…`, `-` for none. So two rooms with
  one key light a cell to the same bytes, and a lamp's level change that crosses a quantum changes the key.

  `litCells().lit(figure, light)`: `const unlit = cellOf(figure)` (the painter's own call, so the unlit hash is paid once,
  as today); the cache key is `unlit.key + '|' + light.key`. The cache holds **only the lit buffer and its key**
  (`<w>x<h>:<fnv of lit>`, hashed once on the miss); every call returns `{ ...unlit, rgba: lit, key: litKey }`, so
  `painted`, `normals`, `depth`, `weave`, `anchor` and `direction` are always this frame's. A miss calls
  `lightSprite(figure, light.lighting)` (a new buffer) and drops the oldest past the limit. The lit cell does depend on
  `normals`, which `unlit.key` does not cover; the same colours with other normals is not a case that arises (the same
  picture is the same pose), so the key does not hash them every frame.

  `painter.paint` takes an optional `light: RoomLight | undefined` and returns `cells.lit(figure, light)` when given.
  `paintedFigure` reads the factory's fourth argument: with a `SceneLight` and `options.lit !== false`, each frame calls
  `roomLight((x, y, z, n) => light.tint(x, y, z, n), light.lighting.sun, at, view.azimuth)`.
  `PaintedFigureOptions.lit?: boolean`.
