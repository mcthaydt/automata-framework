# Feel: what a hit feels like

Status: spec, 2026-11-08. Shared parts: [`2026-11-08-content-editors-spec.md`](2026-11-08-content-editors-spec.md)
(package, session, look, words). Plan: [`2026-11-08-feel-plan.md`](2026-11-08-feel-plan.md).

## 1. Why

The Owner, 2026-11-08: "Each editor needs its own plan and spec." Feel was built ahead of its spec (`0651911b`). It lists
what happens in the game and turns each effect into a sentence with fields. That is half an editor. Juice is judged by
feeling it, and the first build never plays anything: a person changes "How hard" from 0.3 to 0.5 and has to run the
game to know what changed. It also leaves out part of the file (the squash spring, how bright a flash is, who freezes,
where a word shows, a phone's buzz) and never says when a value is above a limit and will be cut.

This spec makes Feel an editor you tune by feel: every change plays at once on a small stage beside the sentences, with
the player's own settings (less flashing, no rumble, half strength) one tap away.

## 2. What the content can say today

`@automata/feel` (`content/feel/*.toml`, schema `feel.schema.ts`):

- **Entries**: `on` is a sim event id or a pattern with `*` (any run of characters). **Every** entry whose pattern
  matches fires (`feel.ts matches`), so `player.*` and `player.hit` both play on a hit. Two entries may not have the same
  `on`.
- **Channels** of an entry, each a list of rows:
  - `camera`: `shake`, a trauma 0 to 1 (the shake is its square).
  - `pose`: `hit_stop_ms`, and `target = "subject"` to freeze only what the event is about.
  - `visual`: one of a flash (`flash` colour, `frames`, `alpha`), a tint (`tint` colour, `ms`, `alpha`) or a squash
    (`squash`, an amount).
  - `word`: `key`, a locale key, never text; `at = "subject"`; `ms`, 800 when unset.
  - `haptic`: `strong` and `weak` motors 0 to 1, `ms`, and `phone_ms` for a phone's single buzz.
  - `audio`: `cue`, an audio cue id.
- **Limits** (`limits`): the most shake in pixels, the longest freeze, the most flash frames, the brightest flash.
  Defaults 3 px, 120 ms, 3 frames, 0.85. A value above a limit is cut when played, and `limitWarnings` names it.
- **The squash spring** (`springs.squash`): `f` (how fast, in hertz), `zeta` (how much it wobbles, below 1 overshoots),
  `r` (how it starts: above 1 anticipates, below 0 winds up).
- **The player's settings** (`FeelSettings`): reduce flashing, rumble on or off, strength 0, half or full. Reduced
  motion is read live.

`createFeel` turns events and frame times into a `FeelFrame` of plain data (offset, frozen views, flash, tint, squash,
words, rumbles, cues). It is a pure function of its inputs and an injected clock, so the editor can run it.

## 3. What a person does in Feel

1. **Pick what happens** from a list of the game's events ("When player hit"), or add one. Adding offers the game's
   events by name (section 5) and still takes any typed name or pattern. "Any player event" is offered for `player.*`.
2. **See and change its effects** as sentences, as today: "Shake the screen. How hard: 0.3." Every field in the file is
   there (section 4), and a field above its limit says so beside it: "Above the longest freeze. Players feel 120 ms."
   (only freeze, flash frames and flash brightness have limits a value can pass; a shake's limit is the size of a full
   shake, shown as "At full: 3 px").
3. **Feel it.** A small stage beside the sentences plays the chosen entry: a square that gets hit, with the shake, the
   freeze, the flash or tint, the squash and the word drawn from `createFeel`'s frames. It plays after every change and
   on **Play again**. The rumble plays on a connected pad (Gamepad `vibrationActuator`) or as the phone's buzz
   (`navigator.vibrate`) when the device has one, and the stage says "Rumble: strong 0.5, light 0.3 for 100 ms" when it
   has neither. The sound plays through `@automata/audio-synth` when the game has that cue, and the stage says "Plays
   the sound hit" when it does not.
4. **Try the player's settings** on the stage: **Less flashing**, **Rumble** on or off, **Strength** full, half or off,
   and **Reduce motion**. They change only the preview, never the file, and say so: "Only changes this preview."
5. **See what else plays.** When other entries' patterns also match the chosen event, the canvas says "Also plays: any
   player event" with a link to it, and the stage plays them together, as the game does.
6. **Set the limits** on "Never more than", as today, and **the squash spring** on the same page under "How squash
   moves": **Speed** (`f`), **Wobble** (`zeta`) and **Wind-up** (`r`), with the stage squashing as each one changes.
7. **Rename** what an entry answers ("Answers: player hit", **Change**) and **remove** it, as today.

## 4. Every field, in words

| Row | Field | Words | Control |
| --- | --- | --- | --- |
| camera | `shake` | How hard | 0 to 1, step 0.05 |
| pose | `hit_stop_ms` | How long | 1 to 1000 ms, step 10 |
| pose | `target` | What freezes | Everything / Only what was hit |
| visual flash | `flash` | Colour | text (a colour name or `#rrggbb`) |
| visual flash | `frames` | How many frames | 1 to 30 |
| visual flash | `alpha` | How bright | 0 to 1; unset plays the most allowed ("As bright as allowed (0.85)") |
| visual tint | `tint`, `ms`, `alpha` | Colour, How long, How strong | as today |
| visual squash | `squash` | How much | 0.05 to 2 |
| word | `words` | What it says | text, translatable (`localized()`); the editor sets `key` itself and never shows it |
| word | `at` | Where | Over what was hit / Middle of the screen |
| word | `ms` | How long | 1 to 5000 ms, 800 when unset |
| haptic | `strong`, `weak`, `ms` | Strong motor, Light motor, How long | as today |
| haptic | `phone_ms` | Phone buzz | 0 (none) to 1000 ms; 0 removes the key |
| audio | `cue` | Which sound | a choice of the game's audio cue ids, or typed |

A choice that sets a key's default value removes the key ("Everything" removes `target`), so the file stays as short as
the person wrote it. A word's words live in the row, as a line's do in Writer (Writer spec §4): `@automata/feel` gains
`words` on the word row, `localized()` in its content kind, so translators get it, and the game shows it through
`createContentText`. Cue ids come from the game's `content/audio/*.toml`; a cue the game does not have is allowed and
named: "The game has no sound “hit” yet." The squash spring is one table: setting one of its three values on a file
without it writes all three, the others at their defaults.

## 5. The game's events

The editor cannot run the game's code, and sim events are code (`defineEvent('player.jumped', …)` in `*.event.ts`). So
Feel offers, best first:

1. the ids in `content/generated/events.json` when the game has one (an open choice, section 8);
2. every `on` already named in the game's feel, audio (`event`) and systems files;
3. the events of the extensions whose content the game has (`content/systems` gives `systems.mode`, `systems.caught`;
   `content/dialogue` gives `narrative.line`; `content/cutscenes` gives `cutscene.started`, and so on), read from the
   extensions' own event definitions;
4. what the person types. A name no list knows is kept and shown in words, and the stage still plays it.

This list is `shared/game-events.ts`, so Audio's "When … happens" uses the same one.

## 5b. In play

A feel is made to be felt in the game, so the game must play it. Today nothing does: `feelExtension` registers only the
content kind. `@automata/feel/stage` adds `feelStage`, a renderer `setup` a game passes beside its level scene: it hears
each step's events, and on each frame moves the world by the shake, draws the flash and tint over the playfield, pops
the words and squashes the subject. A served journey edits a feel in Feel, presses Play and sees it (plan Tasks 6, 7).

## 6. Layout

The canvas is a split view, as the Tuner's: the stage and the sentences side by side when the canvas is at least 560 px
wide, the stage on top (at least 200 px tall) when narrower. The panel keeps the list. The stage is drawn on a 2D
canvas with the square at the centre; it never runs the game. Touch targets 44 px, primary actions 48 px. Reduce motion
on the device turns the stage's own motion to the still form `createFeel` gives, as the game does.

## 7. Checks

- Unit: the model's field lines for every row kind and every field in section 4; default-removes-key edits; limit
  words; `gameEvents` from each source; "also plays" from patterns.
- DOM: each field edits the file; a choice to the default removes the key; the stage replays after a change and on
  **Play again**; settings change the preview and leave the file alone; the start page, the read-only page and the
  refused-write message, as today.
- Stage: given an entry and a fixed clock, the drawn frames are `createFeel`'s (offset, flash, squash, word), checked as
  data, not pixels.
- Chromium layout at 390×844 and 820×1180: the split stacks and sits side by side; nothing under 44 px; no scroll
  outside the sentences.
- In play: `feelStage` unit and Chromium tests, and the served journey in `examples/2d-story`.

## 8. Open choices

1. **An events list from the compiler.** Recommended: a built-in generator in `@automata/content` writes
   `content/generated/events.json` (each `defineEvent` id and its file) so every editor can offer the game's real
   events. It is a core change, so it goes to the framework as a request; Feel works without it.
2. **The preview square or the game.** Recommended: the square. Playing the effect in the running game, as the Tuner
   does, needs the game to replay an event on request, which no game does today.
