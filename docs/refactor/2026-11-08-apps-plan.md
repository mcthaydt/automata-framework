# The paid desktop and mobile apps: plan

> **For the agent building this:** work through the tasks in order with the superpowers `executing-plans` skill
> (`test-driven-development` for every code change, `verification-before-completion` before ticking a box). Steps use
> checkboxes (`- [ ]`). Tick a step only when its check has passed, in the same session, and update
> [progress.md](progress.md) at the end of every task (section "Tracking"). No subagents: the Owner allows none.

**Goal:** carry out the [spec](2026-11-08-apps-spec.md): the full editor suite as a Tauri app on macOS, Windows, Linux,
iOS and Android, playing games with no computer on a phone, syncing each game both ways with GitHub, with a Review page
for coding agents' changes; then, as a later stage, MCP access to the editors in the downloaded apps.

**Architecture:** the editors gain three optional ports (`SuiteHost`, `ProjectStore.watch`, `SuiteCommands`) and two
app-only ones (`sync`, `review`); `apps/editor/` fills them. One app page runs on all five platforms. A computer keeps
`automata editor` as a sidecar; a phone keeps the game in the app's folder and plays it through an in-app compile.
isomorphic-git does sync everywhere. Rust does only what a page cannot: windows, the sidecar's life, the play scheme,
secrets, and later the phone's MCP listener.

**Tech stack:** as the stack: pnpm 10 + turbo 2.11, Node 24.21, TypeScript, Vitest 5 (browser mode), Playwright 1.63,
Svelte 5.57, PixiJS 8.22, Zod 4.6.6, Biome. Tauri `tauri =2.12.4`, `tauri-build =2.7.3` (the pins in
`tauri-project.ts`), plugins fs, http, shell, opener, updater at their newest releases at least 14 days old. sucrase (as
the site's playground). isomorphic-git, its newest release at least 14 days old when task 5.1 starts.

**Spec:** [2026-11-08-apps-spec.md](2026-11-08-apps-spec.md), from the [audit](2026-11-08-apps-audit.md). The
[plan audit](2026-11-08-apps-plan-audit.md) (#527) is applied to both: H1 to H5, M1 to M7 and L1 to L3.

**Where it starts:** the editors stack has two tops, both off #508 (`claude/complete-game-journeys`, `89db7336`): the
editors v2 build (`claude/project-thread-q3zxgn`, `2c0c255e` on 2026-11-08) and the shared-editors fixes
(`claude/project-thread-fxu792`, #522, `5cf0825b`). Task 0.1 starts the build branch from a merge of the two (or from
`main` once both have merged) and records the head. File references below are to that merge: the header is v2's
`SuiteHeader.svelte`, the sidebar v2's `shared/kit/nav/Sidebar.svelte`.

**Sessions:** refreshed after 90 minutes. A session ends by ticking its steps, updating `progress.md`, pushing, and
writing a two-line handoff in this file's execution log.

**Pull requests:** one per phase, stacked, opened ready (the Owner, 2026-11-06), with the attribution block. Merge
only on the usual green head (core and parity).

**Engines and devices:** a cloud session has Chromium, WebKitGTK through `tauri-driver` on Linux, and no Mac or
Android SDK. A step marked **(Owner's Mac)** runs on the af-mac runner or by the Owner; it is ticked only with its
output pasted in the execution log. A step marked **(device)** needs a real phone and is the Owner's.

**Copy:** every user-facing string a task adds goes in `docs/refactor/copy.md` (section "Apps") in the same commit and
passes the drunk grandma test: could a drunk grandma tell what is happening and what to press?

**Real-thing rule:** every audit of this area makes a small game in the app, plays it, and confirms what was made shows
in play (the Owner, 2026-11-08 04:17). Task 7.3's journey is that check, kept.

## Global Constraints

- Law 5: the page never imports Effect. The content compile runs in the page only through the pure modules of task 3.1.
- Only `apps/editor/src/shared/tauri/` imports `@tauri-apps/*`; `packages/editor` never does.
- A refused capability fails and says so; a token never goes to a plain file; no licence key check anywhere.
- Never force-push a game's repository. Never write conflict markers into a game file.
- The app, its strings and its bundle never contain "FigureBuilder" or "EnvironmentBuilder" (the Owner, 21:33).
- Touch targets at least 44 px, primary actions 48 px; phone size first.
- Every window-message handler checks source and origin; the app's origins are `tauri://localhost` and
  `http://tauri.localhost` (one list, `apps/editor/src/shared/app-origins.ts`).
- Versions: each new dependency released at least 14 days before it is chosen, pinned exactly, listed in
  `docs/versions.md`.
- Nothing is sold, uploaded to a store's public track or announced before Pixi 3D is public.
- The desktop's first install (task 2.3, step 4's npm half) and any outside tester wait for the first npm release and
  the `@automataframework` rename (audit A5). The app reads package names only from
  `apps/editor/src/shared/framework-packages.ts`, so the rename is one edit there.
- Progress persists (the Owner, 2026-11-08 21:35): nothing the person made lives only in memory; tasks 4.1, 5.1, 5.3, 6.4,
  2.4, 4.2 and 7.3 each test a restart.
- No relay for MCP, now or later.

## Review Focus

1. **A file changes under an open editor while the person is typing.** Expect the conflict dialog, never a silent
   overwrite or a lost keystroke. Test in task 1.2 (an unsaved document plus a watch event).
2. **The app is offline at open, or loses the network mid-push.** Expect "Saved on this device. Not on GitHub yet: no
   internet." and the push retried on the next pull, with no duplicate commit. Test in task 5.3.
3. **A game whose `package.json` asks for a newer framework than the phone app carries.** Expect the words before Play,
   not a blank player. Test in task 3.3.
4. **"Use changes without asking" meets a change that also edits a generated level TOML.** Expect the level regenerated
   from the merged project and the status line's sentence, and the change still used. Test in task 6.4.
5. **Quitting the desktop app during "Getting your game ready…".** Expect npm and the sidecar stopped, and the next open
   to run the install again. Test in task 2.3 (Rust test with a fake long-running child).
6. **The app is closed, or the phone ends it, right after an edit.** Expect the edit in the game's files, a commit not
   yet pushed pushed on the next open with no second commit, the sign-in, the switch and the last game still there.
   Tests in tasks 4.1, 5.1, 5.3, 6.4, 2.4 and 4.2, and the journey of task 7.3.
