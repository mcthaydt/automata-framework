# Feel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task (no
> subagents in this project). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring the built Feel editor in line with its spec: every field of `feel.toml`, the game's events, limit
words, and a stage that plays each change at once with the player's settings.

**Architecture:** `extensions/editors/src/features/feel` keeps its model (pure functions over `FeelContent` that return
`ContentEdit`s) and session. A new `feel-stage.ts` drives `@automata/feel`'s `createFeel` with given frame times, and
`FeelStage.svelte` draws its frames on a 2D canvas. `shared/game-events.ts` gathers event ids for Feel and Audio.

**Tech Stack:** Svelte 5 runes, Vitest 5 (jsdom, Testing Library), Zod 4, `@automata/feel`, `@automata/audio-synth`,
the kit's content documents and `History`.

**Spec:** [`2026-11-08-feel-spec.md`](2026-11-08-feel-spec.md), with the shared
[`2026-11-08-content-editors-spec.md`](2026-11-08-content-editors-spec.md).

**Audit:** [`2026-11-08-feel-plan-audit.md`](2026-11-08-feel-plan-audit.md) (F1 to F11, fixed below). Tasks 6 and 7
were added by it: a feel edited here must be seen in play.

## Global Constraints

- Code lives in `extensions/editors` (`@automata/editors`, private, no changeset). Core never imports it.
- A feature imports only itself and `shared/`; tests import `#src/…`; files at most 600 lines; kebab-case names.
- Every write goes through `ContentSession.change` (span-preserving edits, mtime guard, undo on refusal).
- The preview never writes the file. The editor never runs the game's simulation.
- What a person changes in Feel is seen in play, in a served journey (the Owner, 2026-11-08): Tasks 6 and 7. A journey
  step that could not run is left unchecked and named, never replaced by writing the file directly.
- Copy passes the drunk grandma test; the words are the spec's section 4 table, verbatim.
- Touch targets at least 44 px, primary actions 48 px; design at 390×844 first.
- Failing test first; `pnpm format`, then the package's `test:unit` and `typecheck`, before each commit.

## Review Focus

1. **A pattern entry on the stage.** `player.*` plays with the event `player.example`; entries matching that also play.
   Test in Task 3.
2. **A choice back to its default.** "Everything" removes `target`; "Phone buzz" 0 removes `phone_ms`; an absent key set
   to a non-default inserts it. Test in Task 1.
3. **A file with a mistake.** The stage shows "Fix the file to play it." and plays nothing; nothing writes. Test in
   Task 4.
4. **No pad, no vibrate, no cue.** The stage says what it would do in words and throws nothing. Test in Task 3.
5. **A cue the game lacks.** Kept, shown, and named ("The game has no sound “hit” yet."). Test in Task 5.
6. **A feel edited in Feel, then Play.** The flash and the shake are drawn in the game. Served journey in Task 7.

### Task 6: Feel in play

The Owner's rule (2026-11-08): what a person changes in an editor must be seen in play. Today nothing in a game plays
`feel.toml`: `feelExtension` registers only the content kind and no game calls `createFeel` (audit F1).

**Files:**

- Create: `extensions/feel/src/features/stage/feel-stage.ts`, entry `extensions/feel/src/entries/stage.ts`
  (`@automata/feel/stage`, in `package.json` `exports`); `extensions/feel/tests/unit/stage/feel-stage.test.ts`;
  `extensions/feel/tests/browser/stage/feel-stage.test.ts`; `.changeset/feel-stage.md` (`patch`)

**Interfaces:**

- Consumes: `PixiStage`, `PixiStageHooks` from `@automata/framework` (its render entry, re-exported by the root), `FrameInfo` (`alpha`, `frameMs`); `StepResult` from
  `@automata/sim`; `createContentText` from `@automata/content/locale`.
- Produces: `feelStage(options: { content: () => FeelContent; settings: () => FeelSettings; reducedMotion: () =>
boolean; clock: Clock; text?: ContentText; cue?: (id: string) => void; rumble?: (pulse: Pulse) => void }): {
setup(stage: PixiStage): PixiStageHooks; last(): FeelFrame | undefined }`. `apply(result)` hears `result.events` at
  `result.tick`; `draw(frame)` takes `frame(lastTick, frame.alpha, frame.frameMs / 1000)` (`FrameInfo` has no tick, so
  the drawn tick is the last `apply`'s) and adds its offset to `stage.world`'s position
  after the game's camera wrote it, draws the flash and the tint as a rectangle over the playfield in `stage.ui`, the
  words over the subject's view (or the middle) and scales the subject's view by its squash; a frozen view keeps its
  pose. `last()` is the frame drawn last, for the game's test hook.

- [ ] **Step 1: Write the failing tests.** Unit, with a fake stage and `fakeClock()`: an event the feel answers with a
  flash gives a ui rectangle of that colour and alpha on the next draw and none after its frames; a shake moves
  `stage.world` and the next frame without trauma puts it back exactly; the player's settings (`reduceFlashing`,
  `intensity: 0`) apply; `cue` and `rumble` are called once per firing. Browser (Chromium): a stage with one sprite
  shakes and flashes and reads back the flash colour at the playfield's centre.
- [ ] **Step 2: Run**; fail. **Step 3: Implement.** **Step 4: Run**; pass. `pnpm build`, `pnpm api-report --update`,
  `pnpm agent-skills --write`.
- [ ] **Step 5: Commit** `feat(feel): a game plays its feel on the stage`.
