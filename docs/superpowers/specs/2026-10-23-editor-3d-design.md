## 1. What the Last Light editor does today (measured)

- **Server and client, no framework:** `editor/src/server` has 33 files (a Node server bound to localhost, `EDITOR_TOKEN` for LAN), `editor/src/client` has 21 plain-TypeScript DOM files. The game runs in an iframe through `src/debug/editor-bridge.ts`.
- **The levels editor (P4) is a top-down plan of `blockout.json`** with tools Room, Opening, Door, Lamp, Hotspot, Anchor, Zone, Node and Edge, snap 0.05 m. Rooms are rectangles. There is no 3D view of its own.
- **Edits are span-preserving.** A number or string changes by its exact span, a structural edit (add a room, opening, door, lamp, hotspot, anchor, zone; remove one) inserts or removes one span and copies its siblings' layout, so a file nobody changed stays byte-identical. A batch is all or nothing and one undo step.
- **The game's own validator runs before a write.** A refusal is a 422 with its results and nothing is written. `map.ts` and `level.ts` are generated by the pipeline and are never written by the editor.
- **Around the editor:** change sets (a git branch `edit/<title>` per task), a checks pill, gate pills, Ask (Claude proposes a diff, accept or reject, with a token cap), undo, Ship (push and a compare link).
- **Not reusable as is:** the server is welded to the Last Light repo (the `pipe` commands, gates, frozen contracts, `.claude` hooks), and the client has no touch or Pencil layer of its own beyond 44 pt targets.

## 2. Scope

In: the level editor for Build-style sector levels, as a package that edits a *level profile* (the Last Light blockout format first) with the kit's shell, history, gestures and storage.

| Area | ED3D owns | Comes from |
|---|---|---|
| Format | Zod schema of `blockout.json` and `facility.json`, `expand` into walls and edges, the profile registry | Vendored from the Last Light source at a recorded commit, with its tests |
| Codec | Byte-preserving patch of a level file from a model change | Port of `json-edit` and `json-structure` with the TypeScript parser replaced by a small JSON span scanner (§4.5) |
| Checks | The validator rules (§7) as pure functions with locators | Port of `blockout-lib.ts` |
| Model | Level document, selection, the commands in §5.4 | New |
| Views | Plan, dollhouse, walk, world (renderers and tools) | New; the mockups are the contract |
| Shell, history, gestures, widgets, storage | Nothing | `editor-kit` |

Out, with where it lives instead:
- The Last Light server, change sets, gate pills, Ship and the `pipe` generators stay in that repo. The editor reaches them only through the ports in §4.4 (`ChangeSet`, `Generator`, `AskProvider`), none of which AF ships an implementation of in v1.
- A native AF 3D level format. The framework's 3D part comes after the editors (GAME-3D, M9), so the format is designed then, as an amendment to this spec, and arrives as a second profile.
- Dress and prop files (`dress.ts`, `props.ts`), room-visibility policy (`visibility.ts`) and camera-zone *previews*. They are Last Light code, not level data (editor-gaps #21, #27, #36). The editor edits the `zones` data and reports a policy it cannot read as a check warning.
- Rendering the game. The editor draws blockout geometry only.

## 4. Ownership and architecture

Dependency direction: `editor-3d` → `editor-kit` → `@mcthaydt/automata-ui` (geometry only) and Svelte. `editor-3d` never imports `editor-2d`, a game, or Last Light code. The kit never imports `editor-3d`.

```
packages/editor-3d/
  src/format/      *.schema.ts   blockout, facility; expand.ts (walls, edges, sector queries)
  src/codec/       patch.ts, locate.ts, layout.ts      byte-preserving writes (ED3D-D4)
  src/checks/      *.check.ts, run.ts                   pure rules with locators (§7)
  src/model/       level.document.ts, *.command.ts      document, selection helpers, commands (§5.4)
  src/view/        plan/, dollhouse/, walk/, world/     projection math, drawing, hit testing, tools
  src/app/         Svelte screens and inspector cards   one folder per mockup screen
  src/ports/       change-set.ts, generator.ts, ask.ts  interfaces only (§4.4)
  src/testing/     fixtures, FakePointer re-export, seeded violations
```

Contract owners: this spec owns the profile and port shapes; `editor-kit` owns everything in §2's last row. A kit gap becomes a change request in the editor PR that needs it.

### 4.1 Level profile

```ts
interface LevelProfile<D> {
  readonly id: string                                // 'last-light-blockout'
  readonly schema: z.ZodType<D>
  parse(text: string): ParseResult<D>                // schema errors carry JSON paths
  patch(text: string, before: D, after: D): PatchResult   // byte-preserving, or { ok: false, path, reason }
  checks(doc: D, facility?: Facility): Check[]
  materials: Material[]                              // { id, category, preview, wallOnly? }
  hints: { unit: 'm'; eyeHeight: number; fov: number; snap: number }
}
```

`id`, `schema`, `parse` and `patch` are the file codec, delivered by ED3D.1 as `FileCodec<D>`; `LevelProfile<D>` extends it with `checks`, `materials` and `hints` as their rows land (ED3D.2, ED3D.8). `facility.json` has a `FileCodec` of its own and no profile.

### 4.2 Document and selection

The `History` state is `{ level: D, facility?: Facility, view: ViewState }`. `view` holds mode, active layer, hidden and locked layers, camera and grid; only `level` and `facility` are saved, but view changes are not undo steps. Selection ids are stable strings: `sector:hall`, `wall:hall/4` (the index of the corner the wall starts at), `prop:cart`, `hotspot:monitor`, `lamp:3`, `zone:1`, `node:n7`.

### 4.3 Geometry owner

`expand` is the single source of walls, edges and sector queries (point in sector, wall normals, shared-wall overlap). The plan, the 3D meshes, hit testing and the checks all read it; no view re-derives geometry. A change to `expand` is a format change with its tests.

### 4.4 Ports

```ts
interface ChangeSet { current(): Promise<{ title: string; branch: string } | undefined>; begin(title: string): Promise<void>; record(files: string[]): Promise<void> }
interface Generator { command: string; run(): Promise<{ ok: boolean; log: string }> }
interface AskProvider { propose(prompt: string, scope: Selection, budget: number): Promise<Proposal> }   // Proposal = a model diff plus token use
```

AF ships none of the three. The Last Light server implements them for its own repo. The editor treats a missing port as "feature off" and never as an error.

### 4.5 Codec

The codec turns *old text + new model* into *new text* and changes nothing it was not asked to. It has four parts, each a pure function with no DOM, clock or `typescript` import.

1. **Scanner** (`locate.ts`): one pass over the text that yields, for every value, its JSON path, kind and `[start, end)` span, plus each object member's key span and each container's span. It accepts exactly what `JSON.parse` accepts (JSON whitespace only, no comments, no trailing commas) and throws with an offset otherwise; a duplicate key in one object is refused. It is a port of the browser-safe `scanJson` that the Last Light plan view already has (`editor/src/client/plan.ts`, about 65 lines), extended with member and container spans; Last Light's server used `ts.parseJsonText` only because it could. The Last Light `json-edit` cases run against it, and its literal spans on the five shipped files are compared with a golden list that Last Light's own `listJsonLiterals` produced once at `92e6704` (TypeScript is not a dependency of the package or of its tests).
2. **Layout** (`layout.ts`): reads how siblings are written (indent unit, space inside braces, packed lines up to width 120) so an inserted element looks like its neighbours. Ported from `json-structure`.
3. **Diff** (`patch.ts`): walks the old and the new model together and emits edits.
   - Objects and maps keyed by id (`anchors`, `nav.nodes`, `styles`, `walls`) are matched by key. A changed number or string becomes a literal edit of that value's span; numbers print with at most 4 decimals and no exponent, as Last Light does. A new key is inserted where the schema's member order puts it; a missing key is removed.
   - Arrays whose elements carry an `id` (`rooms`, `openings`, `boxes`, `hotspots`, `lamps`, `zones`) are matched by id: a new id is an insert at its position, a missing id is a removal, a changed element is diffed in place. If the ids that remain are in a different order, the array is diffed by position instead (correct, but a noisier edit; no command in §5.4 reorders).
   - Every other array (`corners`, `holes`, `nav.edges`, `masses`, coordinate pairs) is diffed by position. Equal length: element by element, in place. Different length: trim the common prefix and suffix (deep equality), pair the first `min(removed, added)` elements of what is left and diff each pair in place, then insert the extra new elements or remove the extra old ones after them.
   - A member the schema does not list is kept in the model as an unknown member and carried through untouched, so a diff never deletes it. A value that changes kind (number to object, string to array) is replaced whole, printed in the neighbours' layout.
4. **Apply** (`patch.ts`): all-or-nothing. The edits are checked for overlap, applied from the end of the text to the start, and the result is parsed again; it must equal the new model (Zod-parsed, deep equal) or the whole patch is refused with the path of the first edit that disagrees. The same function backs undo, because undo restores the previous *model* and the next save diffs against the file on disk.

A file nobody changed is byte-identical (the diff of equal models is empty), and every byte outside an edit is unchanged. A patch is refused, with `{ path, reason }` for §8, in four cases: a value that cannot print without loss (not finite, or more than 4 decimals), text the scanner rejects (invalid JSON, a duplicate key in one object), a `before` model that is not what the text parses to, or a re-parse that disagrees with the new model. Nothing is guessed and nothing is reformatted.

## 5. Model and ordered flows

### 5.1 Sectors, walls, things

A **sector** has an id, zone, floor, ceiling, light, an outer loop of corners and optional holes. A **corner** `[x, z, wall?]` starts a wall to the next corner; the wall is solid (a cut or a preset name from the file's `walls` table) or a **portal** (`next`) to another sector, optionally carrying a door, window, trim, texture, `hideFrom` or handrail. The file's `styles` (floor, ceiling and wall textures, trim) and wall presets are shared definitions; the editor lists and applies them, and edits a definition only through an explicit Styles action (ED3D.8). `exports` (old names the generated file keeps) is carried through untouched. **Things** are boxes (collider, seat or door), hotspots, lamps, anchors, the spawn, nav nodes and edges, and camera zones. An **opening** is a connector sector the format derives between two rooms whose facing, axis-aligned walls are at most 0.5 m apart; it is authored as `{ id, from, to, span }` and expanded by `expand`, so the editor draws it from `expand` output and edits it through its span.

### 5.2 Layers

Seven layers, each with show, hide and lock: Sectors, Walls, Props, Hotspots, Lamps, Nav, Zones. A hidden layer is not drawn and not hit; a locked layer is drawn and not hit. Tools belong to a layer and switch it on when picked.

### 5.3 Flows

1. **Open:** profile chosen from the file → `store.read` → `parse` (schema errors listed, nothing opens on failure) → `expand` → checks run once → `History` created, `markClean`. A facility file, when present beside the level, adds the World view.
2. **Draw a sector (Plan, Sector tool):** tap places a corner (Pencil: hover previews the snap target and the edge length, the loupe shows the corner under the tip, the nudge pad moves it by one grid step) → each edge shows its length → Close (button, or tap the first point) → refused if fewer than three corners, self-intersecting, or overlapping another sector → otherwise one transaction adds the sector with the inherited heights. A new wall that lies on a neighbour's wall offers a portal; accepting adds both portals and the reverse in the same transaction.
3. **Edit a sector or wall:** select, then drag a corner or the whole sector (snap to grid, vertices and wall lines), or use the inspector steppers. A drag is one transaction. Moving a corner of a portal wall moves its reverse.
4. **Walk:** Walk mode places the camera at the spawn (or the first sector's centre with a warning) at eye height. Two sticks move and look; tap picks the wall under the crosshair; the inspector shows that wall (solid, portal, door, window; height; material; handrail; hide from camera). Changing it is a command, so Plan and 3D redraw together.
5. **Retexture:** the material sheet (Walls, Floors, Ceilings, Trim, Windows, Doors) applies to this wall, the room, or matching walls, in one transaction.
6. **World:** levels are cards grouped into wings with an offset; phases run in order; joins connect two levels through an opening, a door or a street. Moving a wing, adding a join or editing a lock is a `facility.json` edit through the same codec.
7. **Check:** after every committed step the checks run (debounced, off the pointer path). The checks pill shows errors and warnings; Locate selects and frames the offending sector, wall or point.
8. **Ask (when a provider exists):** the prompt goes with the selection and a token budget → the proposal is applied to a *copy* of the document → shown as a ghost on the plan with its check results → Accept applies it as one transaction; Reject discards it. Accept is disabled while the ghost has check errors.
9. **Save:** `profile.patch` → `store.write(path, text, { mtime })` → `markClean`, delete the autosave. The generate command is shown (and run through the `Generator` port when one exists). A checks error does not block Save; it blocks Ship (a host concern). Conflict and failure behaviour is the kit's (§5 flow 3 there).

### 5.4 Commands

Each is a `defineCommand` with a shortcut where the mockups show one. All are single transactions.

| Group | Commands |

| Sectors | `sector.add`, `sector.moveCorner`, `sector.move`, `sector.split`, `sector.merge`, `sector.duplicate`, `sector.remove`, `sector.setHeights`, `sector.setLight`, `sector.setMaterials` |
| Walls | `wall.setKind` (solid, portal, door, window), `wall.setDoor`, `wall.setWindow`, `wall.setHeight`, `wall.setMaterial`, `wall.setFlags` |

| View | Draws | Selects and edits |

## 7. Checks

Pure functions over the document, each returning `{ id, ok, detail, problems: { message, locator }[] }`. A `locator` is a selection id plus an optional point, which is what Locate and the plan markers use. Ported from `blockout-lib.ts` unless marked new.

| Check | Fails when |
|---|---|
| `expand` | The document cannot be expanded: an unknown wall preset or style, an opening whose rooms do not exist, or an opening whose two rooms do not have exactly one pair of facing axis-aligned walls covering its span |
| `ids` | An id is duplicated or a reference (door box, nav edge door, lamp kind) does not resolve |
| `shared-walls` | Two solid walls of different sectors lie on one line and overlap by more than 1 cm |
| `openings` | A portal has no reverse over the same segment, or an opening's door box does not straddle it |
| `puzzle-hotspots` | The profile's puzzle lists a hotspot that is not placed (skipped when the profile has none) |
| `nav` | A node is outside every sector or inside a box; an edge is not clear by the margin with doors open; a hotspot cannot be reached from the spawn within its reach |
| `overlap` (new, gap #28) | Two sectors overlap |
| `materials` (new, gap #28) | A material id is not in the profile's list |
| `lamps` (new, gap #28) | A lamp's colour or range is outside the profile's allowed set |
| `policy` (warning) | The profile's room-visibility policy cannot be read or leaves a new sector without a group |

The rules the Last Light pipeline also runs (`zone-cameras`, `scene`) stay there; the editor lists them as "run by the game" in the checks panel with the generate command.

## 8. Persistence and recovery

- Storage is the kit's `ProjectStore`. On iPad the default is an OPFS workspace the user imports into (a folder or a zip) and exports from; on desktop Chromium a folder handle is the upgrade. The editor never assumes a game checkout.
- Autosave journal, conflict dialog (Keep mine, Take theirs, Save as copy) and quota handling are the kit's. The autosave holds the model, not text, so a Restore re-patches against the file as it is now.
- A file the codec cannot patch byte-exactly is saved only after the editor shows the path it cannot preserve and the choice Save reformatted or Export a copy.
- Closing or hiding the page flushes the journal (kit `visibilitychange` and `pagehide` rule).

## 11. Failure and recovery

| Failure | Behavior |
|---|---|
| Schema error on open | The file does not open; a list of JSON paths and messages with Copy details |
| Codec cannot preserve a change | Save is held; the path and reason are shown; Save reformatted or Export a copy |
| A check throws | The check reports `error` with the exception text; the other checks still run |
| 3D context lost or WebGL unavailable | Plan keeps working; the 3D viewport shows a recover action and the reason; no edit is lost |
| Pointer cancelled mid-draw | The open transaction is cancelled; the draft corners already placed stay until Clear or Close |
| Rotation or keyboard mid-draw | No remount; the draft, tool and sheet detent survive |
| Ask provider fails or exceeds the budget | A toast with the reason; the document is untouched |
| Facility file missing or invalid | World is hidden with a reason; levels still open |
| Autosave newer than the file | The kit's Restore or Discard dialog |
