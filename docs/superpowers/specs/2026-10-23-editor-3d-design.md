## 1. What the Last Light editor does today (measured)

- **Server and client, no framework:** `editor/src/server` has 33 files (a Node server bound to localhost, `EDITOR_TOKEN` for LAN), `editor/src/client` has 21 plain-TypeScript DOM files. The game runs in an iframe through `src/debug/editor-bridge.ts`.
- **The levels editor (P4) is a top-down plan of `blockout.json`** with tools Room, Opening, Door, Lamp, Hotspot, Anchor, Zone, Node and Edge, snap 0.05 m. Rooms are rectangles. There is no 3D view of its own.
- **Edits are span-preserving.** A number or string changes by its exact span, a structural edit (add a room, opening, door, lamp, hotspot, anchor, zone; remove one) inserts or removes one span and copies its siblings' layout, so a file nobody changed stays byte-identical. A batch is all or nothing and one undo step.
- **The game's own validator runs before a write.** A refusal is a 422 with its results and nothing is written. `map.ts` and `level.ts` are generated by the pipeline and are never written by the editor.
- **Around the editor:** change sets (a git branch `edit/<title>` per task), a checks pill, gate pills, Ask (Claude proposes a diff, accept or reject, with a token cap), undo, Ship (push and a compare link).
- **Not reusable as is:** the server is welded to the Last Light repo (the `pipe` commands, gates, frozen contracts, `.claude` hooks), and the client has no touch or Pencil layer of its own beyond 44 pt targets.

## 2. Scope

In: the level editor for Build-style sector levels, as a package that edits a *level profile* with the kit's shell, history, gestures and storage. Two profiles ship in v1: **AF sector** (`af-sector/1`, the native, genre-general format, §4.6) and **Last Light blockout** (imported: the byte-exact round-trip case, and the proof that a shipped game's real levels open and save unchanged).

| Area | ED3D owns | Comes from |
|---|---|---|
| Format | Zod schemas of `af-sector/1`, `blockout.json` and `facility.json`; `build` (AF sector) and `expand` (Last Light) into the one geometry (§4.3); the profile registry | AF sector: new. Last Light: vendored from its source at a recorded commit, with its tests |
| Entities | Typed entity definitions and instances (LDtk style): the Things layer, inspector fields, the definitions editor (§4.7) | New, on the kit's shared field and entity definition shapes (EDK §4.8, proposed) |
| Codec | Byte-preserving patch of a level file from a model change | Port of `json-edit` and `json-structure` with the TypeScript parser replaced by a small JSON span scanner (§4.5) |
| Checks | The generic rules and Last Light's own (§7) as pure functions with locators | Port of `blockout-lib.ts` for the Last Light rules; new for the rest |
| Model | Level document, selection, the commands in §5.4 | New |
| Views | Plan, dollhouse, walk, world (renderers and tools) | New; the mockups (accepted by the Owner) are the contract |
| Shell, history, gestures, widgets, storage | Nothing | `editor-kit` |

Out, with where it lives instead:
- The Last Light server, change sets, gate pills, Ship and the `pipe` generators stay in that repo. The editor reaches them only through the ports in §4.4 (`ChangeSet`, `Generator`, `AskProvider`), none of which AF ships an implementation of in v1.
- Geometry beyond sectors: terrain, foliage, open outdoor worlds, streaming, freeform meshes, room-over-room (§2.1). They arrive as geometry kinds next to sectors (D15), terrain and open worlds in the post-launch milestone. The 3D framework (GAME-3D, M9) may later adopt or replace `af-sector/1`; the format is versioned for that.
- Dress and prop files (`dress.ts`, `props.ts`), room-visibility policy (`visibility.ts`) and camera-zone *previews*. They are Last Light code, not level data (editor-gaps #21, #27, #36). The editor edits the `zones` data and reports a policy it cannot read as a check warning.
- Rendering the game. The editor draws blockout geometry only.

### 2.1 What the sector model covers

**Covered in v1** (sectors, portals, heights, per-wall features, typed entities): first-person and exploration games; shooters and arena levels in the room-and-corridor tradition; horror and adventure; immersive sims; stealth and puzzle interiors; interior and architectural blockouts; and the level layout of any game whose levels are sectors plus entities (the game maps each entity definition to its own objects). Last Light is one such game, not the model.

**Not covered yet:** floors that are not flat inside a sector, one sector stacked over another (Build's sector-over-sector), freeform meshes and imported props as geometry, and **terrain, foliage, open outdoor worlds and world streaming**. The last group is the **post-launch terrain and open-world milestone** in the master plan (editor and framework together, Owner 2026-10-23); the rest come with the 3D framework as profile or format amendments.

### 4.1 Level profile

```ts
interface LevelProfile<D> {
  readonly id: string                                // 'af-sector' | 'last-light-blockout'
  readonly schema: z.ZodType<D>
  parse(text: string): ParseResult<D>                // schema errors carry JSON paths
  patch(text: string, before: D, after: D): PatchResult   // byte-preserving, or { ok: false, path, reason }
  geometry(doc: D): Geometry                         // what the views draw and hit (§4.3)
  entities(doc: D): EntityKit                        // definitions, instances and how edits map back (§4.7)
  checks(doc: D, context?: ProfileContext): Check[]  // generic rules plus the profile's own (§7)
  materials(doc: D): Material[]                      // { id, category, preview, wallOnly? }
  hints: { unit: 'm'; eyeHeight: number; fov: number; snap: number }
}
```

`id`, `schema`, `parse` and `patch` are the file codec, delivered by ED3D.1 as `FileCodec<D>`; `LevelProfile<D>` extends it with `geometry` and `checks` (delivered by ED3D.1b), `entities` (ED3D.1b2), `materials` and `hints` (ED3D.8) as their rows land. The profile registry picks a profile from the file (`format` member for `af-sector`, shape for the Last Light files) and lists the ones installed. `facility.json` has a `FileCodec` of its own and no profile. The editor core, the views and the commands import `LevelProfile`, never a profile.

### 4.2 Document and selection

The `History` state is `{ level: D, facility?: Facility, view: ViewState }`. `view` holds mode, active layer, hidden and locked layers, camera and grid; only `level` and `facility` are saved, but view changes are not undo steps. Selection ids are stable strings: `sector:hall`, `wall:hall/4` (the index of the corner the wall starts at), and `entity:<definition>/<id>` for any instance of an entity definition (`entity:lamp/3`, `entity:hotspot/monitor`, `entity:spawn/spawn`). The Last Light profile keeps its familiar names as definition ids.

### 4.3 Geometry owner

A profile's `geometry(doc)` is the single source of walls, edges and sector queries (point in sector, wall normals, shared-wall overlap) and the only way geometry reaches the editor. It returns a list of **geometry layers**; v1 has one kind, `sectors` (for Last Light, `expand`'s output; for `af-sector`, the output of `build`). The plan, the 3D meshes, hit testing and the checks all read it and draw every layer in the list; no view re-derives geometry. A change to `expand` or `build` is a format change with its tests. For the Last Light profile the owner is `expand` plus the game's own sector resolution and nav clearance (`src/game/sectors.ts`, `nav.ts`), ported in ED3D.1c: a `ResolvedMap` is the `sectors` layer's payload and a `NavWorld` answers the clearance queries. That list-of-layers shape is the whole terrain seam (D15): a second kind next to `sectors` is added by a new layer type, with no change to the views' contract.

### 4.4 Ports

```ts
interface ChangeSet { current(): Promise<{ title: string; branch: string } | undefined>; begin(title: string): Promise<void>; record(files: string[]): Promise<void> }
interface Generator { command: string; run(): Promise<{ ok: boolean; log: string }> }
interface AskProvider { propose(prompt: string, scope: Selection, budget: number): Promise<Proposal> }   // Proposal = a model diff plus token use
```

AF ships none of the three. The Last Light server implements them for its own repo. The editor treats a missing port as "feature off" and never as an error.

**Note, 2026-10-30 (EDS.1b):** these ports moved to `@mcthaydt/automata-editor-kit/ports`, whose shapes the [editor suite spec](./2026-10-30-editor-suite-design.md) §4.3 owns: `ChangeSet` gains `checkpoint`, `ship`, `close` and `list` (and `current()` its `base`), `Generator` became a declared check with `joins` (`CheckDef`), and `AskProvider.propose` takes one request object with the level's `path` added; `Proposal` is unchanged. `packages/editor-3d/src/ports/ports.ts` is deleted.

### 4.5 Codec

The codec turns *old text + new model* into *new text* and changes nothing it was not asked to. It has four parts, each a pure function with no DOM, clock or `typescript` import.

1. **Scanner** (`locate.ts`): one pass over the text that yields, for every value, its JSON path, kind and `[start, end)` span, plus each object member's key span and each container's span. It accepts exactly what `JSON.parse` accepts (JSON whitespace only, no comments, no trailing commas) and throws with an offset otherwise; a duplicate key in one object is refused. It is a port of the browser-safe `scanJson` that the Last Light plan view already has (`editor/src/client/plan.ts`, about 65 lines), extended with member and container spans; Last Light's server used `ts.parseJsonText` only because it could. The Last Light `json-edit` cases run against it, and its literal spans on the five shipped files are compared with a golden list that Last Light's own `listJsonLiterals` produced once at `92e6704` (TypeScript is not a dependency of the package or of its tests).
2. **Layout** (`layout.ts`): reads how siblings are written (indent unit, space inside braces, packed lines up to width 120) so an inserted element looks like its neighbours. Ported from `json-structure`.
3. **Diff** (`patch.ts`): walks the old and the new model together and emits edits.
   - Objects and maps keyed by id (`anchors`, `nav.nodes`, `styles`, `walls`) are matched by key. A changed number or string becomes a literal edit of that value's span; numbers print with at most 4 decimals, rounded, and no exponent, as Last Light does (so the saved file can differ from the in-memory model by less than 0.00005 m; the re-parse check compares against the rounded model). A new key is inserted where the schema's member order puts it; a missing key is removed.
   - Arrays whose elements carry an `id` (`rooms`, `openings`, `boxes`, `hotspots`, `lamps`, `zones`) are matched by id: a new id is an insert at its position, a missing id is a removal, a changed element is diffed in place. If the ids that remain are in a different order, the array is diffed by position instead (correct, but a noisier edit; no command in §5.4 reorders).
   - Every other array (`corners`, `holes`, `nav.edges`, `masses`, coordinate pairs) is diffed by position. Equal length: element by element, in place. Different length: trim the common prefix and suffix (deep equality), pair the first `min(removed, added)` elements of what is left and diff each pair in place, then insert the extra new elements or remove the extra old ones after them.
   - A member the schema does not list is kept in the model as an unknown member and carried through untouched, so a diff never deletes it. A value that changes kind (number to object, string to array) is replaced whole, printed in the neighbours' layout.
4. **Apply** (`patch.ts`): all-or-nothing. The edits are checked for overlap, applied from the end of the text to the start, and the result is parsed again; it must equal the new model (Zod-parsed, deep equal) or the whole patch is refused with the path of the first edit that disagrees. The same function backs undo, because undo restores the previous *model* and the next save diffs against the file on disk.

A file nobody changed is byte-identical (the diff of equal models is empty), and every byte outside an edit is unchanged. A patch is refused, with `{ path, reason }` for §8, in four cases: a number that cannot be written (not finite, or one that needs an exponent), text the scanner rejects (invalid JSON, a duplicate key in one object), a `before` model that is not what the text parses to, or a re-parse that disagrees with the new model. Nothing is guessed and nothing is reformatted.

### 4.6 AF sector format (`af-sector/1`)

The native format, a hand-formatted JSON file the same codec patches. It reuses the sector vocabulary Last Light proved (corner loops `[x, z, wall?]`, solid walls and portals, doors, windows, trim, heights, light) and leaves out the pieces that are Last Light's own: camera-zone `hideFrom` and `cut`, the nav graph and its derivation, openings as connector sectors, `exports`. Sketch (exact schema in the ED3D.1b plan):

```json
{
  "format": "af-sector/1",
  "name": "depot",
  "materials": { "brick": { "category": "walls" }, "tile": { "category": "floors" } },
  "sectors": [
    { "id": "hall", "floor": 0, "ceiling": 4, "light": 1, "style": "brick",
      "corners": [[0, 0], [8, 0, { "next": "dock" }], [8, 6], [0, 6]] },
    { "id": "dock", "floor": -0.5, "ceiling": 4, "light": 0.7,
      "corners": [[8, 0], [14, 0], [14, 6], [8, 6, { "next": "hall" }]] }
  ],
  "entityDefs": [
    { "id": "spawn", "shape": "point", "single": true, "fields": [{ "id": "facing", "type": "angle", "default": 0 }] },
    { "id": "crate", "shape": "box", "size": [1, 1, 1], "fields": [{ "id": "loot", "type": "ref", "to": "item" }] }
  ],
  "entities": [
    { "def": "spawn", "id": "spawn", "x": 1, "z": 1, "facing": 0 },
    { "def": "crate", "id": "crate1", "x": 3, "z": 2, "loot": "key" }
  ]
}
```

- **Sectors** have an id, floor, ceiling, light, an optional style (floor, ceiling and wall textures and trim from a `styles` table, as Last Light), and an outer loop of corners with optional holes. A corner's third member is a wall: solid fields, a portal (`next`), a door or a window. A portal needs a reverse over the same segment (check `openings`).
- **`materials`** is the table the picker shows (D10); `entityDefs` and `entities` are §4.7.
- **Versioning:** `format` names the version; the schema keeps unknown members; a newer minor version opens with a warning, a newer major refuses to open.
- **Not in the format:** terrain, props as meshes, scripting, game rules. A game maps entity definitions and sectors to its own objects; AF adds no runtime meaning to an entity in v1.

### 4.7 Entity definitions (LDtk style)

A Things layer is generic over *definitions*. A definition is `{ id, label?, shape: 'point' | 'box', size?, sit?, area?, single?, color?, fields[] }`; a field is `{ id, type, default?, min?, max?, options?, to? }` with `type` one of `int`, `float`, `bool`, `text`, `enum`, `color`, `angle`, `ref` (to another entity's id or a sector). An instance is `{ def, id, x, z, y?, ...fields }` and validates against its definition. **The shapes of `FieldDef` and `EntityDef` are shared with the 2D editor and live in the kit spec §4.8 (proposed with the 2D lane, one owner)**; ED3D adds only the 3D facts: `shape` is `point` or `box`, `sit` says whether the instance rests on its sector's floor (`floor`, the default) or floats at `y`, `box` carries a size in metres, and `area` (added 2026-10-30, ED3D.7c) names four float fields as the `x0`, `z0`, `x1` and `z1` of a rectangle the plan draws and a drag sets, an empty side open; a thing with an `area` is a marker and need not stand in a sector. The inspector builds a form from the fields; the palette lists the definitions; a definitions editor (ED3D.13) adds, renames and retypes them with a refusal when an instance would no longer validate.

The Last Light profile defines its fixed set (spawn, box, hotspot, lamp, anchor, nav node, zone) through the same mechanism, read-only, and maps each to its array; its instances are written back to those arrays by `patch`. Nothing in the editor core names a Last Light concept. (ED3D.7c, plan `2026-10-30-ed3d-7c-zones-nav.md`: a zone is a point at its `look`, and a definition may name four float fields as an `area`, the rectangle a drag on the plan sets; a nav edge is no thing but a *link* between two nav nodes, which a profile declares as `LevelProfile.links`, added and removed by `addLink` and `removeLink`.)

## 5. Model and ordered flows

### 5.1 Sectors, walls, things

A **sector** has an id, zone (Last Light) or style (AF sector), floor, ceiling, light, an outer loop of corners and optional holes. A **corner** `[x, z, wall?]` starts a wall to the next corner; the wall is solid (written as a cutaway group's name in Last Light, or as wall fields that may start from a `preset` in the file's `walls` table) or a **portal** (`next`) to another sector, optionally carrying a door, window, trim, texture or handrail (Last Light adds `hideFrom`). The file's `styles` (floor, ceiling and wall textures, trim) and wall presets are shared definitions; the editor lists and applies them, and edits a definition only through an explicit Styles action (ED3D.8). Last Light's `exports` (old names the generated file keeps) is carried through untouched. **Things** are instances of entity definitions (§4.7): in AF sector whatever the file defines, in Last Light the fixed set (boxes: collider, seat or door; hotspots, lamps, anchors, the spawn, nav nodes and edges, camera zones). A Last Light **opening** is a connector sector the format derives between two rooms whose facing, axis-aligned walls are at most 0.5 m apart; it is authored as `{ id, from, to, span }` and expanded by `expand`, so the editor draws it from `expand` output and edits it through its span. AF sector has no openings: its portals are drawn on the walls.

### 5.2 Layers

Layers each have show, hide and lock: **Sectors** and **Walls** (geometry), then **Things** with one sub-layer per entity definition the profile lists (Last Light: Props, Hotspots, Lamps, Nav, Zones, the seven layers of the mockups; AF sector: whatever its `entityDefs` define). A hidden layer is not drawn and not hit; a locked layer is drawn and not hit. Tools belong to a layer and switch it on when picked.

### 5.3 Flows

1. **Open:** profile chosen from the file by the registry → `store.read` → `parse` (schema errors listed, nothing opens on failure) → `geometry` → checks run once → `History` created, `markClean`. A file no installed profile recognises does not open and the message names the profiles that exist. A facility file, when present beside a Last Light level, adds the World view.
2. **Draw a sector (Plan, Sector tool):** tap places a corner (Pencil: hover previews the snap target and the edge length, the loupe shows the corner under the tip, the nudge pad moves it by one grid step) → each edge shows its length → Close (button, or tap the first point) → refused if fewer than three corners, self-intersecting, or overlapping another sector → otherwise one transaction adds the sector with the inherited heights. A new wall that lies on a neighbour's wall offers a portal; accepting adds both portals and the reverse in the same transaction.
3. **Edit a sector or wall:** select, then drag a corner or the whole sector (snap to grid, vertices and wall lines), or use the inspector steppers. A drag is one transaction. Moving a corner of a portal wall moves its reverse.
4. **Walk:** Walk mode places the camera at the spawn (or the first sector's centre with a warning) at eye height. Two sticks move and look; tap picks the wall under the crosshair; the inspector shows that wall (solid, portal, door, window; height; material; handrail; hide from camera). Changing it is a command, so Plan and 3D redraw together.
5. **Retexture:** the material sheet (Walls, Floors, Ceilings, Trim, Windows, Doors) applies to this wall, the room, or matching walls, in one transaction.
6. **World:** levels are cards grouped into wings with an offset; phases run in order; joins connect two levels through an opening, a door or a street. Moving a wing, adding a join or editing a lock is a `facility.json` edit through the same codec.
7. **Check:** after every committed step the checks run (debounced, off the pointer path). The checks pill shows errors and warnings; Locate selects and frames the offending sector, wall or point.
8. **Ask (when a provider exists):** the prompt goes with the selection and a token budget → the proposal is applied to a *copy* of the document → shown as a ghost on the plan with its check results → Accept applies it as one transaction; Reject discards it. Accept is disabled while the ghost has check errors.
9. **Save:** `profile.patch` → `store.write(path, text, { mtime })` → `markClean`, delete the autosave. The generate command, when the profile has one (Last Light does, AF sector does not), is shown (and run through the `Generator` port when one exists). A checks error does not block Save; it blocks Ship (a host concern). Conflict and failure behaviour is the kit's (§5 flow 3 there).

### 5.4 Commands

Each is a `defineCommand` with a shortcut where the mockups show one. All are single transactions.

| Group | Commands |
|---|---|
| Sectors | `sector.add`, `sector.moveCorner`, `sector.move`, `sector.split`, `sector.merge`, `sector.duplicate`, `sector.remove`, `sector.setHeights`, `sector.setLight`, `sector.setMaterials` |
| Walls | `wall.setKind` (solid, portal, door, window), `wall.setDoor`, `wall.setWindow`, `wall.setHeight`, `wall.setMaterial`, `wall.setFlags` |
| Things | `thing.add` (any entity definition) and `thing.move`, `thing.remove`, `thing.setField`; for Last Light also nav edge add and remove |
| Definitions (ED3D.13) | `def.add`, `def.rename`, `def.setField`, `def.remove` (refused while an instance would stop validating) |
| World | `wing.move`, `join.set`, `join.remove`, `lock.set` |
| View | `view.mode`, `layer.toggle`, `camera.set` (not undoable) |

## 6. Views

| View | Draws | Selects and edits |
|---|---|---|
| Plan | Sector fills by zone or style, walls by kind (solid, portal, door, window), entities by their definition's colour and shape, Last Light's nav graph and zones, rulers, grid | Everything; the only view that adds geometry |
| Dollhouse | Sectors extruded floor to ceiling with the near walls cut away, props, lamps | Select and highlight; orbit, pitch 30° default |
| Walk | First-person flat-shaded view, minimap, crosshair | Pick a wall, prop or lamp; edit wall properties and materials |
| World | Level thumbnails in wings with offsets, phase timeline, joins table | Move a wing, edit a join or lock, open a level |

Split shows Plan and Dollhouse side by side with one selection. The 3D renderer (ED3D-D6) is fed `geometry(doc)` only, so a mesh can never disagree with the plan. Colours are the `Editor 3D` variables (`ent/*`, `view/*`).

**As built (ED3D.5d, [plan](../plans/2026-10-30-ed3d-5d-plan-view.md)):** the Plan view is `ui/plan/PlanCanvas.svelte` over a WebGL2-only Pixi renderer (`ui/plan/plan-renderer.ts`, loaded lazily so Home carries no Pixi) that strokes and fills a paint list (`view/plan/plan-paint.ts`): fills coloured by zone or style (a hash of the group's name into eight muted fills, so a zone keeps its colour across levels), walls by kind, doors and windows as pieces over their span, things by their definition's colour (point, box footprint, or dashed area), links between linked things, the grid, and the selection in the accent; rulers are text over the canvas. The kit's gestures feed `plan-controller` (`ui/plan/plan-gestures.ts`): two fingers pan and pinch, the wheel pans or (with Ctrl or Meta) zooms, a two-finger tap undoes and three redo, a Pencil never pans. The layers panel shows each layer and thing definition with Hide/Show and Lock/Unlock; below `wide` it is the shell's drawer, opened by a Layers button. The views (Plan; Split, 3D, Walk, World disabled with a reason) show at `wide` only; the checks pill is in the bar except on a phone, where its words lead the status line. A page without WebGL2, or a lost context, shows a notice saying the level is safe, with Try again. The colours are the mockups' `ent/*` and `view/plan` values in `view/plan/plan-colors.ts`.

## 7. Checks

Pure functions over the document, each returning `{ id, ok, detail, problems: { message, locator }[] }`. A `locator` is a selection id plus an optional point, which is what Locate and the plan markers use. The **generic** rules run on any profile; the **Last Light** rules are ported from `blockout-lib.ts` and run only on that profile. Each profile lists its own set.

Generic (new unless noted):

| Check | Fails when |
|---|---|
| `ids` | An id is duplicated, or a reference (a portal's `next`, an entity `ref` field, a door box, a nav edge door, a lamp kind) does not resolve. Ported for Last Light, extended for entity refs |
| `openings` | A portal has no reverse over the same segment (Last Light also: an opening's door box does not straddle it) |
| `shared-walls` | Two solid walls of different sectors lie on one line and overlap by more than 1 cm. Ported |
| `overlap` (gap #28) | Two sectors overlap |
| `materials` (gap #28) | A material id is not in the profile's list |
| `entities` | An instance names an undefined definition, misses a required field, has a value outside its field's range or options, is outside every sector, or breaks a `single` definition (two spawns) |
| `heights` | A sector's ceiling is not above its floor, or a portal's two sides leave no opening |

Last Light only:

| Check | Fails when |
|---|---|
| `expand` | The document cannot be expanded: an unknown wall preset or style, an opening whose rooms do not exist, or an opening whose two rooms do not have exactly one pair of facing axis-aligned walls covering its span |
| `puzzle-hotspots` | The profile's puzzle lists a hotspot that is not placed (skipped when the profile has none) |
| `nav` | A node is outside every sector or inside a box; an edge is not clear by the margin with doors open; a hotspot cannot be reached from the spawn within its reach |
| `lamps` (gap #28) | A lamp's colour or range is outside the profile's allowed set |
| `policy` (warning) | The profile's room-visibility policy cannot be read or leaves a new sector without a group |

The rules the Last Light pipeline also runs (`zone-cameras`, `scene`) stay there; the editor lists them as "run by the game" in the checks panel with the generate command.

## 8. Persistence and recovery

- Storage is the kit's `ProjectStore`. On iPad the default is an OPFS workspace the user imports into (a folder or a zip) and exports from; on desktop Chromium a folder handle is the upgrade. The editor never assumes a game checkout.
- Autosave journal, conflict dialog (Keep mine, Take theirs, Save as copy) and quota handling are the kit's. The autosave holds the model, not text, so a Restore re-patches against the file as it is now.
- A file the codec cannot patch byte-exactly is saved only after the editor shows the path it cannot preserve and the choice Save reformatted or Export a copy.
- Closing or hiding the page flushes the journal (kit `visibilitychange` and `pagehide` rule).
- *As built (ED3D.5b, [plan](../plans/2026-10-30-ed3d-5b-app-core.md)):* an import lands under one root folder (the picked folder's name, a zip's single top folder, or the zip's name), a taken root becomes `name 2`, and OS files, unsafe paths and entries over 16 MB are skipped with the reason; zips are read with `fflate`. Save reformatted writes `JSON.stringify(model, null, 2)` and a newline, guarded by the file's mtime; Export a copy downloads the patched text, or the reformatted one when the patch refuses. The facility beside a Last Light level is `facility.json` in its folder, else in a sibling folder.
- *As built (ED3D.5c, [plan](../plans/2026-10-30-ed3d-5c-scaffold-home.md)):* Home is the kit's `HomeScreen` (shared with the 2D editor) with **Import folder** and **Import zip**; a card shows a level's file, its profile's id and its check counts, a facility shows "Opens with a level" and does not open alone (World, ED3D.9c). A file that does not open shows the error panel: one row per problem with its JSON path (`sectors.0.floor`, `(file)` for the root), the profile that read it and the installed ones, **Copy details** (all of it as text) and Open another; nothing is written. A refused patch holds Save in a dialog with the path and the codec's reason, **Save reformatted** (primary) and **Export a copy**; a Save while held reopens it without writing. Restore or Discard and the conflict dialog are the kit's. Leaving a level flushes its journal and lets its facility go too. The components live in `src/ui/` and reach the editor only through `app/` (`architecture.test.ts`).

## 11. Failure and recovery

| Failure | Behavior |
|---|---|
| Schema error on open | The file does not open; a list of JSON paths and messages with Copy details |
| File no installed profile recognises, or a newer major `format` | The file does not open; the message names the format found and the profiles installed |
| Codec cannot preserve a change | Save is held; the path and reason are shown; Save reformatted or Export a copy |
| A check throws | The check reports `error` with the exception text; the other checks still run |
| 3D context lost or WebGL unavailable | Plan keeps working; the 3D viewport shows a recover action and the reason; no edit is lost |
| Pointer cancelled mid-draw | The open transaction is cancelled; the draft corners already placed stay until Clear or Close |
| Rotation or keyboard mid-draw | No remount; the draft, tool and sheet detent survive |
| Ask provider fails or exceeds the budget | A toast with the reason; the document is untouched |
| Facility file missing or invalid | World is hidden with a reason; levels still open |
| Autosave newer than the file | The kit's Restore or Discard dialog |

## 15. Open questions (answers will come from the Owner through the Orchestrator)

1. Where does a Last Light level file come from on an iPad? Default: import a folder or zip into the OPFS workspace and export back; the Last Light server stays the way to edit a live checkout.
2. Should the editor run the game's generate step itself when a `Generator` port exists, or only show the command? Default: show it, run it on one tap.
3. Is `facility.json` editing (wings, joins, phases, locks) in scope for the first release? Default: yes, ED3D.9, because the World view is half of the LDtk idea.
4. Do the placeholder materials stay until the art folder defines the real set? Default: yes.
5. Does the 3D framework (GAME-3D, M9) adopt `af-sector/1` as its level format, replace it, or leave it an editor format a game converts from? Default: leave the decision to M9; the format is versioned so any of the three is possible and nothing before M9 depends on it.
6. Is the editor's entity vocabulary enough for the first non-Last-Light game, or does it need typed references to assets (sounds, meshes) in v1? Default: `ref` covers entities and sectors only; asset refs come with the first game that needs them.
