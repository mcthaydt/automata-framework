## 1. From Ruken: consumed, not copied

AF depends on these Ruken packages directly (vendored tarballs until Ruken publishes them) and mirrors none of their logic.

| Ruken source | AF consumer | How |
|---|---|---|
| `packages/sdk` (`@ruken/sdk`) | `host` ruken adapter | Wrapped as the `Hosting` service's Ruken layer. Handshake, origin/source checks, saves engine, catalog timeouts all come from the SDK. |
| `packages/protocol` (catalog, capabilities, limits, error codes) | `host`, `runtime` | Read through the SDK's exported types. AF never redefines a message, capability or limit. Private in Ruken today; AF uses what the SDK re-exports. |
| `packages/sdk-host` (`src/testing` fake host) | `testing`, `cli dev` | The fake Ruken host for unit, DOM and browser journeys. Replaces AF's planned "mock Ruken host page". |
| `packages/manifest` (`@ruken/manifest`: `parse.ts`, `types.ts`, `origins.ts`) | `ship`, `content` | `ruken.toml` is generated by AF and then parsed by Ruken's parser in CI; the generator's types come from Ruken's `types.ts` (schema 1). |
| `packages/validation` (`archive`, `size`, `file-types`, `manifest-check`, `preload-list`) | `ship` | The same checks Ruken runs on upload run before upload. Exact consumption (package import or `ruken publish --dry-run`) is decided in the M1 spec. |
| `tooling/ruken-cli` (`pack.ts`, `publish.ts`, `run.ts`, `embed.ts`) | `ship`, `cli` | `cli publish` calls `ruken publish`; AF does not reimplement upload. |
| `packages/ui` (Button, IconButton, Dialog, Toast, `theme.css`, tests) | `ui` | Reference for component tests and token structure. AF's primitives match Ruken's interaction rules; game themes stay in games. Branding is not copied. |
| `docs/versions.md`, `tooling/versions/pins.ts` | repo root | AF adopts the same pins page and pins test. |
| `docs/self-hosted-runner.md`, `.github/workflows/playthrough.yml`, `e2e/playthrough/floorfifty.spec.ts` + `floorfifty.sha` | `ship` | Runner setup is reused. Ruken's pinned-SHA playthrough of a game is the model for AF's "reference game on AF" checks in M8. |
| `docs/00`–`04`, `AGENTS.md`, `docs/04-how-we-build.md` | AF docs | Doc system, gate vocabulary (implemented, locally verified, CI verified, deployed, Owner accepted), per-milestone contract freezes. |

Ruken platform services (identity, saves storage, ledger, billing, distribution, the game host's build store and CSP compilation) are never duplicated in AF.

## 4. Not extracted

- FloorFifty: `content/` characters, stages, songs, modes, unlocks; `packages/shared/src/simulation/` (Planck race, lava, survival, CPU); `packages/asset-contract`; race-specific server rooms; `deploy/bin/ruken-runners*`; art.
- The Last Light: `src/scenes/{prologue,clinic,bay}/*`; `render/characters.json`, `render/models/*`, `public/art`, `docs/art`, `docs/narrative`, `docs/design`; `src/ui.ts` HUD; `main.ts` scene wiring.
- The Last Light uses Miniplex; its ECS code ports onto the Koota facade (ADR 0001) rather than being copied. For `puzzle` and `systems` this is a rewrite, not an extraction: the source tests (route tests, probes, bot playtests) come across as behavior specs and are re-pointed at the Koota version, and a test that cannot be ported is listed in that extension's spec with the reason.
- Physics: FloorFifty's Planck race simulation stays in FloorFifty. The Last Light uses `@dimforge/rapier3d-compat` 0.21; AF's `physics` extension uses Rapier's deterministic-compat build (spike S2), and The Last Light moves to it only when it adopts AF.
