## 1. Goal and boundaries

M1.6 delivers the pieces every AF screen is built from, designed for a phone first:

1. **One geometry owner.** It classifies the form factor and height tier, computes the usable region after the safe area and Ruken's `hostReserved` strip, tracks what the browser lays over the page's foot (the on-screen keyboard, a bottom toolbar) and passes on Ruken's `scale` hint. It publishes the result once, as data attributes and CSS custom properties on the document root and as a readable store.
2. **Seven primitives:** `ScreenFrame`, `ActionBar`, `CornerControls`, `ScrollList`, `Dialog`, `LoaderOverlay`, `ErrorPanel`, with theme tokens for targets, gutters and rows.
3. **Basic focus navigation:** one Tab-order model shared by keyboard and controller (next/previous, arrow keys, confirm, back, recovery after a screen change, modal scope).
4. **Testing support in `packages/testing`:** the reference sizes, layout assertions (hit testing, target size, clipping, overlap, reachability, document scroll, intrusion into reserved areas) and renderer-free fixture mounting, used by this lane's own layout contracts at every reference size, including 780×270.

Observable result: every primitive mounts with production styles and fixture data, with no renderer, host or server, and passes its layout contract at every reference size in Chromium, WebKit and Firefox.

**Not in M1.6** (and where it goes):

| Split, OptionGroup, PagerDots, back gesture, page swipe, touch controls, cursor policy, pad guard, steer/page/adjust on the focus navigator, DuckDuckGo hidden-bar heuristics | M4 input and display |

## 3. Contracts

### 3.1 Geometry (`@mcthaydt/automata-ui`, `geometry/`)

```ts
type FormFactor = 'phone-portrait' | 'phone-landscape' | 'tablet-portrait' | 'desktop'
type HeightTier = 'short' | 'compact' | undefined
interface Insets { top: number; right: number; bottom: number; left: number } // CSS px, >= 0
interface Rect { x: number; y: number; width: number; height: number }

/** Structural subset of Ruken's DisplayMetricsPayload (protocol meta/types.ts). */
interface HostDisplay {
  safeArea: Insets
  hostReserved: { edge: 'left' | 'right'; rect: { x: number; y: number; w: number; h: number } }
  scale: 1 | 1.333
}

interface GeometryInput {
  layout: { width: number; height: number }        // innerWidth x innerHeight
  visual?: { height: number; offsetTop: number }   // visualViewport, when the browser has one
  envSafeArea: Insets                              // env(safe-area-inset-*), read by a probe
  host?: HostDisplay                               // absent standalone
}

interface Geometry {
  layout: { width: number; height: number }
  formFactor: FormFactor
  heightTier: HeightTier
  insets: Insets              // per side: max(env, host safeArea, hostReserved strip on its edge)
  hostReserved: { left: number; right: number }
  usable: Rect                // layout less insets
  visualInsetBottom: number   // what the browser lays over the foot; never changes formFactor or heightTier
  visible: Rect               // usable less visualInsetBottom
  scale: 1 | 1.333
}

measureGeometry(input: GeometryInput): Geometry           // pure
applyGeometry(root: HTMLElement, g: Geometry): void        // writes §3.2
createGeometryOwner(options: {
  window: ViewportWindow; root: HTMLElement
  host?: HostDisplay
  timers?: { set(fn: () => void, ms: number): unknown; clear(handle: unknown): void }
  readEnvSafeArea?: () => Insets
}): GeometryOwner

interface GeometryOwner {
  readonly geometry: ReadableAtom<Geometry>   // nanostores; Svelte's store contract
  setHostDisplay(display: HostDisplay | undefined): void
  remeasure(): void                           // now and after each settle delay
  dispose(): void
}
```

Rules:
- **Form factor** from the layout viewport only: portrait (height > width) is a phone below 600 px wide, else a tablet; landscape is a phone below 500 px tall, else desktop. Opening a keyboard changes `visual`, never `layout`, so it never reclassifies or remounts a screen.
- **Height tier** from the layout height: `compact` below 340, `short` up to 600 inclusive, otherwise none. 780×270 is compact; 844×340 is short. M1.7 may add an optional `tierHeight` to `GeometryInput` (the letterbox band); that is additive.
- **Insets:** `hostReserved` becomes a left or right strip of `max(0, rect.w)` on its edge (FloorFifty `reservedOf`). Each side takes the largest of the env inset, the host safe area and the strip. Standalone, host values are 0.
- **Visual inset:** `max(0, layout.height − visual.height − visual.offsetTop)`, rounded to whole px.
- **Settling:** after every `resize` of the window or visual viewport, the owner measures at once and again at 100, 400 and 1000 ms (FloorFifty `SETTLE_DELAYS_MS`); a newer event restarts the delays. Timers are injected so tests use fake ones.
- **Scale** is the host hint (1.333 on Ruken's TV mode), published for tokens to enlarge text and targets; it is never applied as CSS `zoom`.
- **Owner:** exactly one owner per document. Writers: the owner alone writes §3.2. Readers: primitives (through CSS), runtime and renderer (through the store). `dispose()` removes listeners, clears timers and leaves the last values on the root.

### 3.2 What the owner publishes on the root

| Name | Value |
|---|---|
| `data-form-factor` | the form factor |
| `data-height` | `short` or `compact`; absent otherwise |
| `data-visual-inset` | present while `visualInsetBottom > 0` |
| `--af-inset-top/right/bottom/left` | `insets`, px |
| `--af-host-reserved-left/right` | the strip widths, px |
| `--af-visual-inset-bottom` | px |
| `--af-scale` | 1 or 1.333 |

### 3.3 Theme tokens (`theme.css`)

`--af-target: calc(44px * var(--af-scale))`, `--af-target-primary: calc(48px * var(--af-scale))`, `--af-gutter` (16 px; 12 short; 8 compact), `--af-row-h` (the target), `--af-ring-room` (focus-ring reach), `--af-text-body`, `--af-text-small`, and neutral colour roles (`--af-surface`, `--af-panel`, `--af-ink`, `--af-muted`, `--af-accent`, `--af-danger`, `--af-scrim`, `--af-edge`). Games override colours and type; they never lower the targets. Decoration and gutters shrink under `data-height`; targets do not.

### 3.4 Primitives

Every visible string is a prop. Every interactive element is a native `button` (or the control the role needs) at least `--af-target` square, `--af-target-primary` tall for primary actions. `testId` props render as `data-testid`.

| Component | Props (summary) | States and behavior |
|---|---|---|
| `ScreenFrame` | `arrangement: 'stack' \| 'split'`, `corners?`, `hero?`, `body`, `actions?` snippets | Fills `visible` (fixed; inset by `--af-inset-*`, ends above `--af-visual-inset-bottom`). Row 1 is the corner row, in flow, never over content. Stack: hero takes what the body leaves, so on a short screen the hero shrinks first. Split: hero and body side by side. Body is the `af-screen` size container. While `data-visual-inset` is present it scrolls rather than leaving an action under the overlay. The screen root picks the arrangement from form factor and tier; the frame never branches on them. |
| `CornerControls` | `back?: () => void`, `backLabel`, `header?`, `end?` snippets | One row, the target's height. Back at the start, `end` (a game's Mute, a language flag) at the end, header centred on the screen's centre line. |
| `ActionBar` | `actions: BarAction[]` (`id`, `label`, `shortLabel?`, `icon?`, `kind: primary \| secondary \| utility`, `onSelect`, `disabled?`, `pressed?`) | Collapse levels measured from hidden rows: 0 full labels; 1 utilities to icon; 2 secondaries to short label; 3 wrap with primary alone. `data-collapse` shows the level; a layout contract fails a reference size that reaches 3. A shortened button keeps its full label as its accessible name. |
| `ScrollList` | `minRows`, `rowCount`, `label`, `moreLabel: (n) => string`, `rowGap?`, `children` | A declared scroll region (`data-scroll-region`, `role="region"`). Reserves `min(minRows, rowCount)` rows so siblings shrink before a row is lost. Counts rows below the fold into a "+N more" label that never takes taps. |
| `Dialog` | `title`, `onclose`, `children?`, `actions?` | Ruken's Dialog: `role="dialog"`, `aria-modal`, initial focus on `[data-initial-focus]` else first control else the panel, Tab wraps, focus pulled back in, restored on close, Escape calls `onclose`. A bottom sheet on phone form factors, centred otherwise; within the insets and above the visual inset; its body scrolls (declared region) so its actions stay reachable at 780×270. |
| `LoaderOverlay` | `label`, `progress?: number` (0–1; absent = indeterminate), `slow?: boolean`, `slowLabel` | Covers the screen; `role="progressbar"` with `aria-valuenow` when determinate; the slow line holds its height and is `aria-live="polite"`. |
| `ErrorPanel` | `code`, `message`, `actions: [ErrorAction, ...ErrorAction[]]` (`id`, `label`, `kind: primary \| secondary`, `onSelect`) | `role="alert"`, `data-code`. At least one action, enforced by the type and by a runtime check that throws in development: a failure with no way forward is a bug, not a state. Sits at the top of `usable`, under the corner row when the layer is narrow, passing taps through outside the panel. |

### 3.5 Focus navigation (`focus/focus-nav.ts`)

`tabbables(root)`, `arrowKeyNav(event)`, `scrollWithin(element)`, `PAD_FOCUS`, and `FocusNavigator` with `attach(target)`, `move('next' | 'previous')`, `recover()`, `confirm()`, `back()`, `setPaused(paused)`. Order is DOM order, the same as Tab. The topmost open, non-inert `[aria-modal="true"]` is the whole world while open. `recover()` acts only while the controller is engaged (the last input was the navigator, not a pointer or a real key). `back()` dispatches an Escape keydown marked in `padKeyEvents` so dialogs close through one path. No steer, page, adjust or pad guard in M1 (M4).

## 4. Lifecycle and flows

1. **Boot (M1.5 wires it):** the runtime creates the owner before the first screen mounts, passing the host's display metrics when hosted; the owner measures and applies synchronously, so the first frame of the first screen already has `data-form-factor` and insets.
2. **Resize, rotation, browser bar, keyboard:** event → measure → apply → store update → settle re-measures. A keyboard changes only `visualInsetBottom`/`visible`; screens stay mounted.
3. **Host display change:** `setHostDisplay` → measure → apply. Undefined returns to standalone values.
4. **Screen change:** the new screen calls `remeasure()` on mount (a WebView's bars can settle with no event); `FocusNavigator.recover()` puts focus on the first control if the controller is engaged.
5. **Dialog:** mount → remember opener → initial focus → trap → Escape/action → page unmounts it → focus restored to the opener.
6. **Dispose:** listeners removed, timers cleared; disposing twice is a no-op.

## 5. Failure policy

| Case | Behavior |
|---|---|
| No `visualViewport` | Visual inset 0; everything else unchanged |
| `env()` unreadable (jsdom, old engine) | Probe yields 0 per side |
| Host metrics with a negative or absent strip width | Clamped to 0 |
| Host display missing standalone | Standalone values; never a guess at a host |
| `ResizeObserver` missing (jsdom) | ActionBar stays at level 0, ScrollList at its token reserve; components still mount |
| `ErrorPanel` with no actions | Type error; throws in development |
| Dialog with nothing focusable | Focus stays on the panel |
| A reference size where an ActionBar reaches level 3, a control is off screen outside a scroll region, smaller than its target, covered at its centre, overlapping the corner row, or under a reserved strip | The layout contract fails with the problem list |

## 6. UI inventory and responsive behavior

| Primitive | Phone portrait | Phone landscape incl. 780×270 | Tablet / desktop | Keyboard open | `hostReserved` | TV scale |
|---|---|---|---|---|---|---|
| ScreenFrame | stack; corner row, hero shrinks first | stack or split; compact gutters | split or stack | ends above it, scrolls its content | content inset by the strip | targets 1.333× |
| CornerControls | one row | one row | one row | unchanged | Back/end clear of the strip | 1.333× |
| ActionBar | collapses by width, never level 3 | one row | one row | reachable by scrolling the frame | clear of the strip | 1.333× |
| ScrollList | reserves its rows; "+N more" | reserves ≥1 row; "+N more" | full | scrolls | — | — |
| Dialog | bottom sheet | sheet, body scrolls, actions reachable | centred | above it | inside the insets | 1.333× |
| LoaderOverlay | centred | centred | centred | — | — | — |
| ErrorPanel | top, under corner row | top, under corner row | top | — | inside the insets | — |

Focus and input: every primitive works with touch, mouse, keyboard and the navigator; input mode never changes layout. Long text: labels wrap or shorten (ActionBar `shortLabel`), never shrink a target; dense locales are M5's matrix.

## 11. Exit criteria

Success:
1. `@mcthaydt/automata-ui` exports the geometry owner, the seven primitives, `theme.css` and focus navigation per §3; `@mcthaydt/automata-testing` exports §3.6.
2. Unit and component tests pass; `pnpm check` passes with the two packages included.
3. Every layout contract passes at every reference size and variant in Chromium, WebKit and Firefox, run locally on Node 24; the run's counts and timings are recorded in the PR.
4. The sim parity suite still passes in all three browsers.

Failure cases that must be demonstrated by tests: a keyboard opening never changes `data-form-factor`; 780×270 classifies `phone-landscape` + `compact`; an ActionBar too wide for 360 px reaches level 2 and not 3; a control under a 48 px right strip is reported; an `ErrorPanel` without actions does not render; a Dialog at 780×270 keeps both actions reachable.

Gates reported separately: implemented, locally verified, CI verified (blocked: hosted runners), Owner reviewed (this spec), Owner visual acceptance (not claimed; M1.8).
