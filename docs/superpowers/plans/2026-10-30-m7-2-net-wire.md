## Interfaces

```ts
// net (the wire is the one owner; server imports it)
export type JoinOptions = { protocol: number; schemaHash: string; contentHash: string; name: string; session?: string }
export type ClientMessage =
  | { t: 'cmd'; seq: number; tick: number; type: string; payload: unknown }
  | { t: 'ping'; id: number; tick: number } | { t: 'ready'; ready: boolean; req: string }
  | { t: 'bot.add' | 'bot.remove' | 'leave'; req: string; seat?: number }
export type ServerMessage =
  | { t: 'snap'; tick: number; hash: string; acks: Record<string, number> } | { t: 'seated'; seat: number }
  | { t: 'pong'; id: number; slack: number } | { t: 'answer'; req: string; error?: NetErrorCode } | { t: 'replay' }
// net/sim
export const NetOwner: ComponentDef            // 'net-owner' { seat: u32 }
export const SeatJoined, SeatLeft: CommandDef   // 'seat.join', 'seat.leave' { seat }
export const SeatJoinedEvent, SeatLeftEvent: EventDef  // 'seat.joined', 'seat.left' { seat, sid }
export const netPlugin: PluginDef
// net/testing
export interface Transport { send(data: string | Uint8Array): Effect.Effect<void>; onMessage(listener): () => void }
export function createLink(options: { seed; latencyMs; jitterMs; loss; duplicate; reorder }): { client: Transport; server: Transport }
```

Deviation recorded for review: the spec names `seat.joined` and `seat.left` as both the commands and the events; the
sim keys commands and events in separate maps, but one id meaning two things in replays and logs is confusing, so the
commands are `seat.join` and `seat.leave` and the events `seat.joined` and `seat.left`.

`netPlugin` semantics: `seat.join { seat }` spawns one entity `[net-owner { seat }]` if the seat has none, and emits
`seat.joined { seat, sid }`; a second join for a held seat does nothing. `seat.leave { seat }` despawns every entity
whose `net-owner.seat` is that seat and emits `seat.left { seat, sid }` for the seat entity; leaving an empty seat
does nothing. Only the server sends them (M7.3 applies them); the sim does not check who sent them.

`createLink`: each `send` draws, from a `createRng(seed)` stream per direction, whether the message is lost
(`loss`), duplicated (`duplicate`) and held back (`reorder`, an extra `latencyMs` delay); its delay is `latencyMs`
plus a uniform draw in `[0, jitterMs)`. Delivery is an `Effect.sleep` forked as a daemon, so it runs when `TestClock`
reaches it. Probabilities are in `[0, 1]`; a bad option throws.

## As built (deviations)

- The seat bound (`MAX_SEATS`, `seatSchema`) lives in `src/sim/seat.schema.ts`, and the wire re-exports it: the sim
  may import only inside its own folder (`pnpm boundaries` refused `../wire/primitives.schema`), so the sim is the
  one owner and the wire imports from it.
- Relative imports have no `.ts` suffix and the exported schemas carry hand-written types (`z.ZodType<T, Input>`),
  as in the framework's packages (`isolatedDeclarations`).
- `createLink` delivers through a per-end pending queue: each copy forks one sleeper, and whichever wakes first
  delivers everything due, earliest first and in send order on a tie. Plain per-message fibers delivered two
  messages due at the same instant in reverse send order.

- `ping.tick` is a finite number from 0, or exactly -1 (FloorFifty's probe); the spec writes `uint`, and the fraction
  is what measures slack finer than a tick. `bot.remove` requires a seat; `bot.add` and `leave` take none.
- The seat system applies joins and leaves in send order (seq, then source) and keeps entities released this tick out
  of later commands, because despawns wait for the end of the tick.
- `createLink`'s sleepers are daemon fibers with no close: under `TestClock` nothing runs unless the clock moves, and
  a live-clock user is M7.6's headless client, which can scope it then.
