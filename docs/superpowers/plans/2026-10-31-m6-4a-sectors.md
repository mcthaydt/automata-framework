## Scope

In: `packages/sectors` with its sim side only: the `sector-map` content schema (the format's types, no new field),
`resolveMap` on `@mcthaydt/automata-sim/math`, the queries (`sectorAt`, `floorAt`, `segmentBlocked`), the step rule,
the Koota plugin (`sector-map` resource, `in-sector` component, `sector.entered` and `zone.crossed` events), optional
static `Collider3D`s when `physics` is registered, the extension definition, a four-engine golden, SC-a and SC-c.

Out (M6.4b): meshes, UVs, dressing, cutaways, shade and the occluder feed, the `sectors-room` example, SC-b. Out
(M6.5): nav. `rooms.ts`'s safe-room helpers (`isSafe`, `withSafeRooms`) are `systems`' concern (M6.7); only
`sectorAt` comes across here.

## Part 0: core prerequisites (blocking; found while writing this plan)

Checked at `core.ref` `b7ef19d`:

1. **editor-3d is not importable from Plus shipped code.** `@mcthaydt/automata-editor-3d` is `private: true`, so
   core-packs does not pack it (Plus's `tooling/core/sync-core.ts` `EXTRAS` holds only `@mcthaydt/evidence`), and
   Plus's F1 rule (`tooling/boundary/core-imports.ts`) allows a private core pack in test files only.
2. **editor-3d has no sim entry.** Its only export is `.` (`src/index.ts`), which re-exports the editor's Svelte UI
   and `@mcthaydt/automata-editor-kit`. `pnpm boundaries` lets a sim file import a package only through an entry the
   package lists in `automata.simEntries`. The `format/` files import only `zod` and each other, so they are
   sim-safe as they stand.
3. **The format's constants live in the editor's geometry.** `WALL_THICK`, `STEP` and `DEFAULT_TRIM` are defined in
   editor-3d `src/geometry/sectors.ts`, not in `format/`. The sim needs all three.
4. **`SectorDef` has no schema.** It is a TypeScript interface in `format/expand.ts` (with `Corner`); `format/` has
   Zod schemas for walls, trims, windows, doors and masses but none for a sector or a corner, so a `sector-map`
   content schema cannot validate one without redefining it.

## Interfaces

Consumed: `SectorDef`, `Corner`, `MassDef`, `WallDef`, `Point`, their schemas (`sectorDefSchema` and `cornerSchema` new
in 0a), `OCCLUDES`, `WALL_THICK`, `STEP`, `DEFAULT_TRIM`
(editor-3d `./format`, after 0a); `defineComponent`, `defineResource`, `defineEvent`, `definePlugin`,
`defineExtension`, `sortedKeys` (`@mcthaydt/automata-sim`); `hypot` (`@mcthaydt/automata-sim/math`);
`defineContentSchema` (`@mcthaydt/automata-content`); `Transform3D`, `Collider3D`, `RigidBody3D`, `BodyKind`,
`ShapeKind` (`@mcthaydt/automata-physics/3d`, optional).

Produced (spec §4.3; the names are the spec's):

```ts
export interface SectorMap { readonly sectors: readonly SectorDef[]; readonly masses?: readonly MassDef[] }
export interface ResolvedMap {
  readonly sectors: readonly Sector[]
  readonly masses: readonly MassDef[]   // the given masses plus the pilasters' masonry
  sectorAt(p: Point): Sector | undefined
  floorAt(p: Point): number | undefined // undefined outside the map (the source returned 0)
  segmentBlocked(a: Point, b: Point, margin?: number): boolean
}
export function resolveMap(map: SectorMap): ResolvedMap
export const sectorsPlugin: PluginDef
export const sectorsExtension: ExtensionDef<'sectors'>
export type { Point } // re-exported from the format (§3)
```

`floorAt` returns `undefined` outside the map, as the spec's signature says; the source's `?? 0` is a caller's choice.
`segmentBlocked(a, b, margin = 0)` is true when the plan segment crosses, or comes within `margin` of, a walk-blocking
piece (a solid wall, or a portal whose lower step is taller than `STEP`), using `segmentDistance`.

Events: `sector.entered { entity, sector: string, from: string | undefined }`; `zone.crossed { entity, zone: string,
from: string | undefined }`, where a sector's zone is its `zone` field (the source's `crossed` probe), emitted only
when the zone changes. Membership is decided on the fixed step from `Transform3D` x/z, in entity id order.

## Decisions for the Owner's veto

- **S4-D1 (0a):** the format gets its own sim-safe entry, `@mcthaydt/automata-editor-3d/format`, owns
  `WALL_THICK`, `STEP` and `DEFAULT_TRIM`, and gains `cornerSchema` and `sectorDefSchema` for its existing `Corner`
  and `SectorDef` types (no new field). This is M6-D15's fallback ("the format moves to its own core entry with no
  shape change") taken now, because `sectors`' sim cannot import the editor's root entry. Alternative: a separate
  core package for the format (more surface for no gain while editor-3d is the only other consumer).
- **S4-D2 (0b):** a private Plus package may import a private core pack; published Plus packages still may not.
  Alternative: publish editor-3d (against "the editors stay private") or copy the format into Plus (against one
  contract owner).
- **S4-D3:** the resolved map stores indices instead of object references (the source's `Edge.sector`, `next`,
  `prev`, `succ`), so the resource is plain data for hashing and snapshots. Behavior is unchanged.
- **S4-D4:** `floorAt` returns `undefined` outside the map (the spec's signature), not the source's 0.
- **S4-D5:** SC-a compares coordinates within 1e-12 and topology exactly, because the sim's geometry is dmath and the
  source's is `Math`. The editor's float geometry is not changed.
