## Scope

In (`tooling/pipelines`, a `blockout` pipeline beside `puzzle`, `systems`, `narrative` and `audio`; free: no stage is paid, none is gated):
- **`blockout.pipe.toml`:** `blockout` (the spec file, JSON, inside the folder), `maps` and `nav` (the content folders the generated files go to,
  relative to the folder), optional `[shots]` (below).
- **`validate`** (fails closed, exit 1, writes nothing but `validate.json`): the schema (`blockoutSchema`), then `expand` (a `BlockoutError` is a
  finding at its message), then the generated `sector-map` through `sectorMapSchema` and `resolveMap` (SC-c), the generated `nav-graph` through
  `navGraphSchema`, then the generic checks ported from the source's `validate` as plain findings: unique ids across rooms, openings, boxes and
  zones; every opening's door is a door box that straddles its line; no door-role box without an opening; no `on` attachment to nothing; both
  sides of a portal agree; no nav edge through a box; every nav node reachable from the spawn's. Findings name their path.
- **`generate`:** writes `maps/<scene>.toml` (`sector-map`) and `nav/<scene>.toml` (`nav-graph`) from the expansion, each stamped on its first
  line with `# blockout xxh64:<hash of the spec text>` and "Generated by `automata pipe blockout`; do not edit". Same spec, same bytes.
- **`check`:** validate is clean; both generated files exist and carry the current stamp; a hand edit (the body differs from what the stage
  makes, stamp current) and a stale stamp are told apart and named. The `generated` globs in the folder's `pipeline.toml` are what M3.8c's guard
  reads; the pipeline's own `check` is the proof until that row lands.
- **`shots`** (needs a runner; off unless the spec has `[shots]`): for each camera zone, where to stand (the spawn or a nav node inside the zone,
  the source's rule), one run of the configured command with the zones as JSON on stdin; it writes `grey-<zone>.png`. Each shot is read back
  (PNG decoded in plain TypeScript) and judged legible: luminance mean and the 10th-90th percentile spread within the spec's bounds. A zone with
  no standing point is skipped and listed. Writes `shots.json`. The command is the game's (the dev server and the debug driver); the pipeline
  never starts a server itself.
- **`import <sector-map.toml> <nav-graph.toml>`** (one-off, refuses to overwrite without `--force`): an existing map and graph as a blockout
  spec: each sector a room (walls and portals kept as written), each mass kept, the nav written by hand (`derive: false`), a TODO list of what
  the file cannot know (zones, anchors, openings).
- **EP-a and EP-b** as tests; a fixture spec (`two rooms, a doorway, a door`) is the fixture `base-adventure` (M6.12) will start from.

Out: the source's puzzle-hotspot binding, lamp checks and `facility` command (game-specific, M6 §1), `scene shots`, the python leveller, and the
guard itself (M3.8c).

## Decisions for the Owner's veto

- **BP-D1:** `validate` is the generic half of the source's checks. The editor's `checks/` carry the same rules as editor `Problem`s with
  locators; they stay the editor's (private), and the pipeline has its own plain-finding versions. Default: no more core moves.
- **BP-D2:** the shot runner is a command in the spec, not built in: M6.12's `base-adventure` supplies it. Legibility bounds are spec fields
  (defaults mean 60-200, spread 40), judged on the raw shot: the source judged after a python levelling pass that is not ported.
- **BP-D3:** `import` reads the content files a game has, not its code, so it works for any game; zones, anchors and openings are not
  recoverable from them and are listed as to do.

- **BP-D4:** `import` is not a router command: the platform's command list is fixed (`run`, `check`, ...) and has no one-off commands, and widening it
  is the pipelines lane's call (M3.8c touches the same files). It is its own bin, `automata-blockout-import <folder> [--force]`, that reads the
  folder's `blockout.pipe.toml` (so it needs no extra arguments) and writes the spec it names. Default: a follow-up may move it into the router.
