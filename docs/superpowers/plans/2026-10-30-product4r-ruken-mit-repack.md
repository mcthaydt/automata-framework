## What is wrong

The four vendored tarballs (`vendor/ruken/`, packed from RukenApp `d0fa2fe` by QB.1f) declare no `license` and carry no `LICENSE` file, so `docs/stack.md` says "not declared in the installed package" for `@ruken/sdk`, `@ruken/sdk-host`, `@ruken/manifest` and `@ruken/cli`, and `build:playground` stops at its manifest: `@ruken/sdk-host@0.0.0 declares no licence; the playground cannot publish it` (checked on `main` `30e9606c`, below). AF's published content, host and ship bundle this code (D-8), so the licence gates the 1.0 release (M8.9, R-16).

The Owner chose MIT ("Yes, MIT it", 2026-10-30). RukenApp PR #396 merged as `e376a2d7971b696f77f1d15f5174e80de70e65ef` (2026-10-30 00:33 -05:00): an MIT `LICENSE` ("Copyright (c) 2026 Dawson McThay", the same text in all four) and `"license": "MIT"` in `packages/sdk`, `packages/sdk-host`, `packages/manifest` and `tooling/ruken-cli`. `git diff d0fa2fe e376a2d --stat` in a scratch clone: those eight files, a changeset and one `cspell.json` word, nothing else.

## Decisions

- **Repack in a scratch clone**, never in `/home/user/rukenapp`: `git clone --depth=20 https://github.com/mcthaydt/rukenapp` into the session scratchpad (HEAD `e376a2d`), `pnpm install --frozen-lockfile`, then `vendor/ruken/README.md`'s recipe (each package's own `pnpm run build`, then `pnpm pack`).
- **Prove that only the licence moved:** extract the new and the `d0fa2fe` tarballs and `diff -r` them. Expected: each new one adds `package/LICENSE` and `"license": "MIT"`; every `dist/` is identical; `pnpm pack` may reorder the `@ruken/*` dev dependencies (QB.1f's finding).
- **`VENDORED.md` carries the licence.** MIT asks that its notice be "included in all copies or substantial portions of the Software", and content, host and ship publish Ruken's code in their `dist/` (ship also copies Ruken's whole CLI build to `dist/vendor/ruken-cli/`). `write-vendored.ts` reads each bundled package's `license` field and `LICENSE` text from its installed copy (the tarball's own declaration, never typed), adds a License column to the table and the text under a License heading (once for the packages that share it). A bundled package with no `license` field or no `LICENSE` file fails the build: a published package never bundles code without a licence. This adds to M2 spec §3.2's "names the RukenApp commit and each bundled Ruken package with its tarball SHA-256" (noted there).
- **The stack page shows a declared licence for every vendored package:** a new case in `stack-page.test.ts` reads the installed packages (red today, green after the repack). `docs/stack.md` is regenerated by `pnpm docs:stack`, never edited.
- **Comments that cite Ruken behaviour "at d0fa2fe"** (`packages/host`: `sdk-markers.ts`, `hosting.ts`, `menu.ts`, `hosting-web.ts`, three tests) stay: they record what was checked at that commit, and the code they describe is byte-identical at `e376a2d` (the `dist/` diff). The one comment that says which commit the vendored CLI was built at (`packages/ship/src/publish/publish-to-ruken.ts`) would go stale, so it points at `vendor/ruken/README.md` instead of naming a commit. No doc comment of a published API changes, so `api-report`, `api-index`, the cheatsheet and `agent-skills` should report nothing to regenerate.
- **A patch changeset only for published packages whose published files change,** found by a forced build diffed against `main`'s (QB.1f's lesson: the turbo cache can replay a stale build). Expected: content, host and ship (their published `VENDORED.md`); ui and testing only if their `dist/` changes (ui inlines the SDK's types, testing one type; the types are identical, and neither publishes a `VENDORED.md`). `cli` is private and never named.
- **Out of scope here:** the website's `/inside` page (`automata-website`, `scripts/sync-stack.ts` copies `docs/stack.md`; a website-lane follow-up once this is on `main`); WEB.PLAY.3's own step 3 test (the manifest lists every file with its sha256): this task only reports whether `build:playground` now passes the licence gate.
