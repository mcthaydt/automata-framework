# DX.4b: document the API baseline TDD plan

- **Spec:** [DX spec](../specs/2026-10-16-dx-small-games-ai-native-design.md) §2.3 ("Exhaustive API reference"), §3.8; [DX.4 plan](2026-10-16-dx4-api-index.md) (the baseline that can only shrink).
- **Task:** `DX.4b — Document the API baseline`, lane ship with each owning lane. `tooling/api-index/undocumented-baseline.json` lists every export with no doc comment (182 on `main` at `1fa4acc`; the row's 184 predates later removals). The index fails when a listed export is now documented (the entry must go), so the list only shrinks and a documented export that stays listed fails CI.
- **Status:** drafted 2026-10-23.
- **Progress:** 4 of 4 steps.

## Decisions

- **The test is the index itself.** `pnpm api-index` already fails on a stale baseline entry and on a stale `docs/cheatsheet.md`. Each slice writes the doc comments first, runs `pnpm build && pnpm api-index` and sees it fail naming exactly the ids the slice documented (red), then deletes those ids and runs `pnpm cheatsheet` (green). No new test code: the check is the gate DX.4 built for this.
- **Slices by owner, four PRs.** (1) `sim` (55 ids across `.`, `./math`, `./replay`); (2) `content`, `host`, `node`, `ship` (48); (3) `testing`, `physics` (44); (4) `ui` (35), last, because the runtime and ui queue is another thread's and a doc-only PR there waits until it is quiet. Each slice is stacked on the one before it, so every branch carries this plan and the baseline it prunes, and they merge bottom-up.
- **What a comment says.** The type's job in one sentence (the cheatsheet shows only the first sentence), then what a caller must know: when it throws, what the values mean, the invariant it keeps. Facts are read from the code, not guessed; a limit or error named in a comment is the one the code uses. Tag-free prose, as the documented exports already are.
- **A misplaced comment is fixed, not duplicated.** `createReplayStepper`'s comment sat above another function's, so TypeScript attached neither to it; it moves to the function it describes.
- **Changeset.** Every slice changes a published package's source (comments reach the emitted `.d.ts`), so each adds a patch changeset.

## Files

- **Modify:** doc comments in `packages/<name>/src/**` for the slice's ids (declarations only; no code changes), `tooling/api-index/undocumented-baseline.json`, `docs/cheatsheet.md` (regenerated by `pnpm cheatsheet`), `docs/02-master-delivery-plan.md` (the DX.4b row, ticked when the baseline is empty), a `.changeset/*.md` per slice.
