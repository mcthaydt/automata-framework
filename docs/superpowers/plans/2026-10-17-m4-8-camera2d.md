## Source

FloorFifty `apps/client/src/systems/gameplay/camera.ts` at `ac72660` (258 lines) and its test file `tests/client/systems/gameplay/camera.test.ts`. Most of that camera is race-specific: the content-fit zoom, the portrait anchor, the danger zoom and the punch stay in FloorFifty, or go to M6's `feel`. AF takes three things from it, each with a behavior test:

- **`damp`.** The value moves toward the target by `min(1, rate · Δt)` of the gap each frame, so it never overshoots. A rate of 0 holds still.
- **Presentation only.** The camera writes the transform of the container it is given and nothing else. A child keeps its own coordinates: FloorFifty's `worldToLogical` is the identity, and AF tests that a child's position is untouched.
- **Read at frame time.** Reduced motion is checked on every update, not cached, because the setting can change while the game is open (`ui` `reducedMotion()`).

## Contract

`packages/render-pixi/src/camera/camera-2d.ts`, exported from `@mcthaydt/automata-render-pixi`:

```ts
export interface CameraRect { readonly x: number; readonly y: number; readonly width: number; readonly height: number }
export interface Camera2dOptions {
  readonly view: { readonly width: number; readonly height: number } // the playfield's logical size (amendment, below)
  readonly follow?: { readonly rate: number; readonly deadZone?: { readonly width: number; readonly height: number } }
  readonly bounds?: CameraRect
  readonly zoom?: number                     // default 1
  readonly reducedMotion?: () => boolean     // default: ui's reducedMotion()
}
export interface Camera2d {
  target(x: number, y: number): void
  shake(trauma: number): void
  update(frameSeconds: number): void
  readonly transform: { readonly x: number; readonly y: number; readonly scale: number }
}
export function createCamera2d(stage: Container, options: Camera2dOptions, seed?: number): Camera2d
```

- **Amendment to spec §4.10.** The amendment is recorded in the spec in this PR; nothing has implemented §4.10 yet, so nothing breaks.
  - `view` is required. To centre a target, the camera needs the size of the area it shows, and a Pixi `Container` has no viewport.
  - `reducedMotion` is optional and injectable, so tests can drive it.
  - `deadZone` is a size centred on the view, not a `Rect`. A rect anchored anywhere other than the centre has no meaning for a follow.
- **Follow.** With `follow`, the desired centre is the target. With a dead zone, the centre moves only enough to bring the target back to the zone's edge. The centre then approaches the desired centre through `damp` at `follow.rate` per second. Without `follow`, the centre is the target.
- **Before the first `target` call.** The first call snaps the centre to the target, with no approach from the origin.
- **Bounds.** The view (`view / zoom`) never shows outside `bounds`: the centre is clamped after follow and after shake. When the bounds are smaller than the view on an axis, the view is centred on them on that axis.
- **Shake.**
  - `shake(t)` adds `t` to the trauma, which is capped at 1.
  - The trauma decays at `SHAKE_DECAY` (1.5 per second).
  - The offset per axis is `SHAKE_MAX_OFFSET` (8 logical px) × trauma² × noise in [−1, 1).
  - The noise comes from a seeded mulberry32 generator (`seed`, default 1), so a visual test is stable.
  - Under reduced motion the offset is 0, though trauma still decays.
- **Transform.** `scale = zoom`, `x = view.width / 2 − centre.x · zoom`, `y = view.height / 2 − centre.y · zoom`. These are written to `stage.position` and `stage.scale` on every `update`.

## Steps

2. [ ] **Red: follow and bounds (C-a).** Create `packages/render-pixi/src/camera/camera-2d.test.ts`. It covers:
   - The first target snaps the centre.
   - `damp` never overshoots: a rate × Δt above 1 lands exactly on the target.
   - At rate 6 and Δt 1/60, a 100 px step settles within 0.5 px after exactly `ceil(ln(0.005) / ln(0.9))` = 51 frames, and not after 50.
   - The dead zone holds the centre while the target stays inside it, and brings the target back to the zone's edge when it leaves.
   - The view never shows outside `bounds`, also at zoom 2 and when the bounds are smaller than the view.
   - The transform matches the formula and is written to the container. A child's position is unchanged.
