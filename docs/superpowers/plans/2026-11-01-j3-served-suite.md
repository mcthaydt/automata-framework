## What is built
1. `servedPorts(store)` (`editor-suite/src/shell/served-ports.ts`): the suite's ports over a served checkout's HTTP store, classed by the checkout's own `content/editors.toml` (no list or a bad one: read only; no change set, so Ship stays hidden).
2. `main.ts`: `openServedWorkspace` (the kit's `/api/ping` + token) decides; served, the page edits the checkout; otherwise the in-memory sample, now named `SAMPLE_GAME` with a neutral fixture (`sample-game.editors.toml`, no source names; the test that required a source commit now requires none).
3. **Bug found by the first end-to-end test:** the server's policy refused to *read* `content/editors.toml` (a `never` path), so the page could never load its own list. `editorPolicy.canRead` now allows reading it; `canWrite` still refuses it (`serve-editor.test.ts` asserts both).
4. **Bug found by the same test:** `suite-session` fired `refresh()` unawaited after each write, so a store that cannot be listed (a stopped server) was an unhandled rejection; it now leaves the pills as they were.

Options for the Owner's veto (default none taken): (a) write the export with each save (needs a one-undo-step multi-file write for editors, and rows for those paths in the list); (b) make the content compiler read the editor project directly; (c) an explicit Export button in the suite.
