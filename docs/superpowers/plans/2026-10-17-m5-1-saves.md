### `packages/runtime/src/save/save.manager.ts` (create)

```ts
export interface Loaded<S> {
  readonly slot: number
  readonly data: S
  readonly meta: SlotMeta
  readonly snapshot?: Uint8Array // only when the snapshot's content hash is the build's (M5-D5)
}
export interface Save<S> {
  readonly slots: Subscribable.Subscribable<readonly SlotState[]>
  load(slot: number): Effect.Effect<Loaded<S>, SaveUnreadable | SaveFromNewerBuild | HostError>
  write(slot: number, data: S, options?: { readonly label?: string; readonly snapshot?: Uint8Array }): Effect.Effect<void, SaveRefused | HostError>
  remove(slot: number): Effect.Effect<void, HostError>
}
export interface SaveServiceOptions {
  /** The build's sim content hash (`GameDefinition.content.hash`), stamped on each write and compared on load. */
  readonly contentHash: string
}
export function saveService<S>(def: SaveDef<S>, options: SaveServiceOptions): Effect.Effect<Save<S>, HostError, Hosting | PresentationBus>
```

**Deviation, for review.** Spec §4.3 writes the signature as `saveService(def)`:
- **The content hash.** The service needs the build's content hash to stamp writes and to tell `other-content`. Nothing in the runtime provides it as a service today; boot holds it as `game.content.hash`. So it is passed as an option. M5.2's boot wiring passes `game.content.hash`.
- **No `Scope`.** M5.1 forks nothing, so the signature drops `Scope` until M5.2's autosave needs one.
- **Error channel `HostError`.** The initial `keys` read can fail, so this is `HostError` rather than `never`.

**Rules:**
- **Boot reads.** `slots` starts from `Hosting.saves.keys`. Only keys that `slotOf` maps to a slot below `count` are read with `get`, and each is classified by `slotState`. Every other slot is `empty`.
- **`slots` is a `SubscriptionRef`.** `write`, `remove` and `load` update the slot they touch.
- **`write`:**
  - A `newer` slot fails `SaveRefused`, and nothing is sent.
  - Otherwise the envelope is built with `savedAt` from Effect's `Clock`.
  - **Dedupe (S-b):** compare the canonical envelope *without* `savedAt` with the last one this service wrote or read for that slot. If equal, nothing is sent and no fact is published.
  - Otherwise `saves.set` runs. Success publishes `save.written { key, slot }`. Failure publishes `save.failed { key, slot, code }` and the error is relayed.
- **Writing over an `unreadable` slot is allowed.** A `write` is the player's explicit choice (§6). The no-touch rule belongs to autosave (M5.2) and to `load`.
- **`load`:**
  - An empty slot loads `def.empty()`, with no `saves.*` write.
  - `unreadable` fails `SaveUnreadable`, and `newer` fails `SaveFromNewerBuild`. Neither ever writes.
  - Otherwise the data is migrated and parsed. The snapshot is returned only if its content hash is the build's.
  - It publishes `save.loaded { key, slot }`.
- **`remove`** calls `saves.remove` and sets the slot `empty`.
