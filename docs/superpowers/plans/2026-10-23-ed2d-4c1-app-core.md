## Decisions made here (written into the 2D spec in this PR)

1. **Only `levelProject` is registered in this slice.** `floorFiftyStage` is in the EDFF stack (#151 to #160), a different base. The registry takes any profile, the app never names one, and `architecture.test.ts` already forbids a profile id string in `app/` (G-s). EDFF.2 adds the second line. Tests plant a second profile to cover the two-profile cases (the choice dialog, a mixed list).
2. **The first export of a profile is its working file.** `exports[0].files(value)[0].path` names a new document, so a profile needs no new member for "the file extension". `level-project` (`<name>.af2d.json`) and `floorfifty-stage` (`content/stages/<id>.toml`) already do this; the sentence goes into the `Profile` docs and spec §7.
3. **A new document is a saved file.** `create` prints the template, writes it to the workspace (a path already taken gets ` 2`, ` 3` before the extension), and returns the result of `open` on it. So Home lists it at once, the editor never holds a document with no file, and every template is proven openable by the same path an existing file takes. No name prompt: the name is a field of the document, edited in the profile's own views.
4. **A document is `History<unknown>`.** The app does not know the profile's value type. The view that does (4c4 maps `ViewDef.component` names to components) narrows once, at the mount.
5. **`base` follows the file.** A codec may patch the text it loaded (`Profile.print(base, value)`), so the app keeps the text as last read or written: `serializeFile` and `snapshot` print against it, and a successful save makes the text it wrote the new base. A failed or conflicting save changes nothing. A restored autosave makes the payload the base.
6. **Reading a file ends in one of six outcomes**, all values, none thrown: `parsed`, `choose` (two or more profiles claim it), `unrecognised` (none does), `invalid` (the profile claims it and `parse` returned errors: the error panel and the text view), `notText` (the bytes are not UTF-8) and `tooLarge` (over 16 MB, before decoding). A newer-version or unknown-key project is `invalid` with the profile's own codes (ED2D.3 made `parse` do that), so the app has no read-only mode of its own.
7. **Opening offers recovery, it does not apply it.** `open` returns `recovery` from the kit's `findRecovery` (or `undefined`); a failure to read the journal opens the document anyway with `recoveryError`. `restore(recovery)` parses the payload with the document's profile and applies it as one undoable step labelled "Restore autosave", which leaves the document dirty (kit spec §5 flow 4); a payload that no longer parses is refused with its errors and nothing changes. `discardRecovery()` removes the journal.
8. **Save is the kit's.** `OpenDocument.save`, `overwrite` and `saveCopy` are the `DocumentSession`'s, wrapped only to keep `base` right. The outcome (`saved`, `conflict`, `failed`) goes to the view; the app opens no dialog.
9. **The project list shows projects, not files.** `list()` returns one entry for each workspace file that at least one profile claims, newest first (then by path). Each says which profile, whether it opens, and how many errors and warnings its checks give (`check(value, { assets })`, with `assets` the workspace paths). A claimed file that does not parse is `broken` with its first error's message; a file two profiles claim is `ambiguous` with the candidates. Images, journals and anything no profile claims are left out.
10. **Duplicate copies the bytes.** The first unused `name copy.ext`, `name copy 2.ext` (the extension starts at the first dot of the file name, so `a.af2d.json` keeps both parts; a dotfile has none). It reads the file and writes the copy, without parsing, so a file that does not open duplicates too (changed during the build from "open, then `saveCopy`": that route refused a broken file, which is the one a person most wants a copy of before repairing). It answers `copied`, `missing` or `failed` (a store that refuses, nothing written).
11. **`remove` deletes the file and its autosave**, and is not an undoable step.
12. **Time and ids are injected.** `clock` (`StorageClock`) drives the memory store in tests, the autosave debounce and `History`'s coalescing; `ids` is the `IdSource` templates need. The app reads neither `Date` nor `crypto`; the entry page of 4c2 passes `randomIds(crypto.getRandomValues)` and the system clock.
13. **A store that refuses is a value too.** `open` and `create` answer `storageFailed` (`reason` is the kit's `StorageFailure`, `message` the store's) when the store denies a read, is full, or cannot be listed, so the screen never has to catch. `list()` is the one call that rejects, with the kit's `StorageError`: without a listing there is no Home to draw, and the shell shows the storage banner.
14. **`open` stats first.** The mtime it hands the session is the one read before the bytes, so a file changed after the read can only make the next save a conflict, never be overwritten silently.

## Contract

```ts
// app/profiles.ts
export function createAppProfiles(): ProfileRegistry          // levelProject, in this slice

// app/read-document.ts
export type ReadOutcome =
  | { status: 'parsed'; profile: Profile<unknown>; value: unknown; text: string }
  | { status: 'choose'; candidates: readonly Profile<unknown>[]; text: string }
  | { status: 'unrecognised'; text: string }
  | { status: 'invalid'; profile: Profile<unknown>; errors: readonly ParseError[]; text: string }
  | { status: 'notText' }
  | { status: 'tooLarge'; bytes: number }
export function readDocument(registry: ProfileRegistry, fileName: string, bytes: Uint8Array, as?: string): ReadOutcome

// app/editor-app.ts
export interface OpenDocument {
  readonly profile: Profile<unknown>
  readonly path: string
  readonly history: History<unknown>
  readonly session: DocumentSession
  save(): Promise<SaveOutcome>
  overwrite(): Promise<SaveOutcome>
  saveCopy(): Promise<SaveOutcome>
  restore(recovery: Recovery): Result<true, readonly ParseError[]>
  discardRecovery(): Promise<void>
  dispose(): void
}
export type OpenOutcome =
  | { status: 'opened'; document: OpenDocument; recovery: Recovery | undefined; recoveryError?: string }
  | { status: 'choose'; path: string; candidates: readonly Profile<unknown>[]; text: string }
  | { status: 'unrecognised'; path: string; text: string }
  | { status: 'notText' | 'missing'; path: string }
  | { status: 'invalid'; path: string; profile: Profile<unknown>; errors: readonly ParseError[]; text: string }
  | { status: 'tooLarge'; path: string; bytes: number }
  | { status: 'storageFailed'; path: string; reason: StorageFailure; message: string }
export type CopyOutcome =
  | { status: 'copied'; path: string }                          // the new path
  | { status: 'missing'; path: string }
  | { status: 'failed'; path: string; reason: StorageFailure; message: string }
export interface EditorApp {
  readonly registry: ProfileRegistry
  readonly workspace: Workspace
  list(): Promise<readonly ProjectEntry[]>                     // rejects with the kit's StorageError
  create(profileId: string, templateId: string): Promise<OpenOutcome>
  open(path: string, as?: string): Promise<OpenOutcome>       // `as`: the profile the person chose after `choose`
  duplicate(path: string): Promise<CopyOutcome>
  remove(path: string): Promise<void>
}
export function createEditorApp(options: { workspace: Workspace; registry: ProfileRegistry; ids: IdSource; clock?: StorageClock }): EditorApp

// app/project-list.ts
export type ProjectEntry =
  | { status: 'ok'; path: string; size: number; mtime: number; profile: { id: string; label: string }; errors: number; warnings: number }
  | { status: 'broken'; path: string; size: number; mtime: number; profile: { id: string; label: string }; message: string }
  | { status: 'ambiguous'; path: string; size: number; mtime: number; candidates: readonly { id: string; label: string }[] }
```

### Deviations

- **Duplicate copies bytes instead of open then `saveCopy`** (decision 10), so a broken file can be duplicated. Returns `CopyOutcome`, not `SaveOutcome`.
- **`storageFailed`** outcome on `open` and `create` (decision 13), not in the plan's contract; `list()` rejects with the kit's `StorageError`.
- **`open` carries `text` for `choose` and `unrecognised`**, so the choice dialog and the text view need no second read.
- **The kit's `./core` entry gained the storage layer** (`openWorkspace`, `createDocumentSession`, `findRecovery`, the stores, `statPath`, `classifyStorageError`, `flushOnHide`). The plan did not name a kit change; `app/` has to run on Node and the root entry loads the Svelte shell. Separate commit, kit spec note under EDK-D2.
- **`Profile.exports[0]` as the working file** is stated in the `Profile` docs and spec §7/§8.1 as planned. The EDFF.1d profile (#160) changes `files(value)` to `files(value, base)`; this branch is built on the pre-#160 interface, so the call in `create` becomes `files(value, '')` where the two meet in main.
- **Time and ids**: `clock` defaults to the system clock when the caller passes none, so the entry page of 4c2 can omit it.
