## Decisions (defaults, for the Owner's veto)

1. **Export is a rail view, not a modal.** The profiles already list `ExportView` as a destination; it draws the mockup's dialog body in the canvas region with its actions at the foot. Leaving it is choosing another rail entry, so it has no Cancel.
2. **Share and Copy take one file.** The kit's share sheet and clipboard take one file or one text. They are enabled when exactly one file is chosen (the working file alone is the common case); otherwise the view says "Share and Copy take one file; Download takes them all."
3. **Clean after an export only where Export is the save.** Flow 9 ends with `markClean`. In a persistent workspace the copy on the device is what Save keeps, so a download does not mark the document clean. In a non-persistent one (memory fallback, "Not saved on this device") exporting the working file marks it clean, as the kit makes Export the primary action there.
4. **A folder write checks every file first.** The view remembers each file's mtime (or that it is absent) when it lists the files. Write to folder first re-lists them; if any changed, the conflict dialog opens and nothing is written (G-m). Keep mine writes every file without the guard; Cancel writes nothing. A failure part-way stops and names the file; the files written before it stay (the store has no transaction).
