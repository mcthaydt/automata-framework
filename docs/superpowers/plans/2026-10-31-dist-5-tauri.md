## DIST.5a

### Interfaces

- **Produces** `@mcthaydt/automata-host/target` under `automata-tauri`: `makeHosting`, `HostingLive` (the same
  signatures as the other adapters). Internally `makeTauriHosting(options, page, desktop)` over a `DesktopPort`:
  `loadStore(): Promise<StoreLike>`, `onCloseRequested(handler): Promise<() => void>`, `exitApp(): Promise<void>`;
  `tauriDesktop()` is the real port (`@tauri-apps/plugin-store` `load('saves.json')`, `@tauri-apps/api/window`
  `getCurrentWindow().onCloseRequested`, `@tauri-apps/plugin-process` `exit(0)`).
- **Produces** `TAURI_MARKERS` and `findTauriMarkers` beside the Ruken markers.
- **Changes** `ui`'s boot failure: with `hostKind: 'tauri'` and `exit` granted, the exit action reads "Quit".
- **Behavior (spec §4.3, §6.1):** the web adapter's lifecycle, input, display, audio and fullscreen; `kind: 'tauri'`;
  `hostName` is the page's `<title>`; `saves` in the store (granted only when it loads; otherwise every call fails
  `DENIED` and nothing is written anywhere; a failed write fails `INTERNAL`, retryable); `flush` saves the store and
  answers `device`; `exit` and the window's close request run the `onExiting` handlers in order, then the flush, within
  `HOST_EXIT_CAP`, then quit.

## DIST.5b

### Decisions (veto defaults)

- **Where `tauri` comes from:** the game's own dev dependency `@tauri-apps/cli` 2.12.3 (`node_modules/.bin/tauri`),
  else `tauri` on `PATH`; ship does not carry Tauri's 15 MB native CLI. `create-game` adds it for desktop games (DIST.6).
- **The generated project** lives in `<game>/.automata/tauri/`, never in the game's source, and is rewritten on every
  `prepare`: `tauri.conf.json`, `Cargo.toml` with exact crate pins (`tauri` =2.12.4, `tauri-build` =2.7.3,
  `tauri-plugin-store` =2.5.0, `tauri-plugin-process` =2.4.0, each at least 14 days old), `build.rs`, `src/main.rs`,
  `capabilities/default.json` (only `core:default`, `store:default`, `process:allow-exit`) and a generated 512 px icon
  (a game may name its own PNG with `tauri.icon`).
- **The webview's CSP** is generated from the game config: Ruken's no-eval policy shape (`script-src 'self'
  'wasm-unsafe-eval'`, no `'unsafe-eval'`) plus Tauri's IPC origins and the config's `network.connect` origins.
- **Bundles per OS:** Linux `deb` and `appimage`, macOS `app` and `dmg`, Windows `nsis` and `msi`, copied to
  `dist-tauri/<id>-<version>-<os>-<bundle>.<ext>` beside the build. Tauri builds only for the OS it runs on.
- **Toolchain** is checked before anything is written: `cargo`, and on Linux `pkg-config --exists webkit2gtk-4.1`;
  a missing piece fails with what to install.
- **Proof:** the Linux bundle is built here from a minimal desktop fixture and recorded in the log (file names, sizes,
  SHA-256); macOS and Windows bundles are built on the runners in 5c. No CI job in 5b (the PC runner is the
  bottleneck; 5c adds an opt-in job).

## DIST.5c

Coordinator, 2026-10-31: no Windows runner (the PC runner is Linux under WSL, `af-linux`; the Owner: "just use the
Mac"), so the Linux bundle is built on `af-linux`, the macOS bundle on `af-mac`, and the Windows bundle stays an Owner
gate; a workflow change goes in its own PR with a "Workflow change" section.

### Decisions (veto defaults)

- **itch.io Downloadable:** `automata-ship publish --target itch --from tauri` pushes one bundle per OS found in
  `dist-tauri/`, each to its own butler channel: Linux the AppImage (`linux`), macOS the dmg (`mac`), Windows the NSIS
  installer (`windows`); `itch.downloads` may rename a channel. butler pushes a folder, so each bundle is staged alone
  in `dist-tauri/.itch/<channel>/`. Same `--userversion` and `--if-changed` as HTML5, and the same early failures (no
  `itch` section, no key, no butler).
- **CI:** `game-release.yml` gains the opt-in `desktop: true` input: a job on `af-linux` and `af-mac` (a matrix of
  two) that builds the game's `build-tauri-command` (default `pnpm build:tauri`), runs `automata-ship prepare --target
  tauri` and uploads `dist-tauri/` as an artifact; with `itch: true` too, it then runs `publish --target itch --from
  tauri`. Never for a pull request.
- **Signing:** with `desktop-signing: true`, the macOS leg runs in the `release` environment and passes the Owner's
  `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY`, `APPLE_ID`, `APPLE_PASSWORD` and
  `APPLE_TEAM_ID` to `tauri build`, which signs and notarizes (https://v2.tauri.app/distribute/sign/macos/); a missing
  secret fails the job by name before building. Unsigned otherwise, and the artifact's name says `unsigned`.
