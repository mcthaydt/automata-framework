## Scope

In: `packages/dev-tools`, the Plus package `@mcthaydt/automata-dev-tools` (0.0.0, `SEE LICENSE IN LICENSE`) with two
bins and nothing to import:

- `promote-evidence --to <baselines> [--from <dir>] [<path> …]`: with no path, lists each file under the evidence
  folder (default `evidence`, git-ignored) that is `new` or `changed` against the committed baselines folder, and
  copies nothing. With paths (a file or a set folder, relative to the evidence folder), copies them across.
- `worktree-gc [--apply] [--base <branch>]`: reports what it would tidy; changes nothing without `--apply`.

Out: capture itself. Evidence is captured by the tests that write it (core's `testing` Playwright helpers and
`tooling/evidence`'s collector own that); `dev-tools` only lists and promotes what they left. FloorFifty's capture
helper (`tests/e2e/support/evidence.ts`, a constant folder path) has no generic behaviour to port.

## Interfaces

```ts
export interface CommandOutput { readonly exit: 0 | 1 | 2; readonly stdout: string; readonly stderr: string }
// 0 done · 1 an unexpected failure (git or a copy failed) · 2 refused or bad usage
export interface WorktreeGcOptions { readonly apply: boolean; readonly base: string; readonly cwd: string }
export function worktreeGc(o: WorktreeGcOptions): Effect.Effect<CommandOutput, never, Files | ProcessRunner>
export interface PromoteOptions { readonly cwd: string; readonly from: string; readonly to: string; readonly paths: readonly string[] }
export function promoteEvidence(o: PromoteOptions): Effect.Effect<CommandOutput, never, Files | ProcessRunner>
```

Every git call is `git -C <dir> …` through `ProcessRunner`, so the unit tests answer git from a fake and one
integration test runs real git on a temporary repository.

### `worktree-gc` rules

1. The main checkout is the first entry of `git worktree list --porcelain`; "this checkout" is
   `git rev-parse --show-toplevel` from the working folder. The base is `origin/<base>` after a successful
   `git fetch -q origin <base>` (default `main`), else the local `<base>`.
2. `git worktree prune --dry-run -v` is printed; `--apply` runs `git worktree prune`.
3. A worktree other than the main checkout and this one is **kept**, with its reason, when it is locked; has a
   running process whose working folder is inside it (`lsof -w -d cwd -Fpn`); cannot be checked for processes (`lsof`
   missing or failing); has anything in `git status --porcelain` (untracked included); has commits not in the base
   (`git rev-list --count <base>..HEAD`); or has commits on no remote (`git rev-list --count HEAD --not --remotes`).
   A git check that fails also keeps it. Otherwise it is reported `remove`, and `--apply` runs
   `git worktree remove <path>` (never `--force`, so git refuses a dirty tree a second time) and
   `git branch -d <branch>` (which refuses an unmerged branch).
4. Scratch (`playwright-report/`, `test-results/`) in a worktree that is not the main checkout, not locked and has no
   running process (or none can be checked) is reported, and removed with `--apply`.
5. A folder under `<main>/.claude/worktrees/` that git does not list is reported `orphan` and never removed.
6. Without `--apply` the last line is `(report only: --apply to act)`, and no mutating git call or file removal runs.

### `promote-evidence` rules

1. The root is `git rev-parse --show-toplevel`; `--from` (default `evidence`) and `--to` (required) are relative to it.
   No evidence folder: exit 2. Files whose name starts with `.` are skipped.
2. Listing compares each evidence file with its baseline by `cmp -s` (`new`, `changed`; same files are not listed).
3. A path selects the evidence file of that name or every file below that folder. A path that is absolute, leaves
   the folder through `..`, or selects nothing is refused (exit 2) and **nothing** is copied.
4. A selected `evidence.json` (core's evidence file) is read with `EvidenceFileReaderSchema` before anything is
   copied: a file that does not parse, was made from a dirty tree (`revision.dirty`), or has a golden whose engines
   disagree (`enginesAgree: false`) is refused (exit 2), and nothing is copied.
5. Each selected file is copied with `mkdir -p` and `cp` through `ProcessRunner` (`Files` reads and writes UTF-8 text
   only, so a PNG cannot go through it; a request to core, below), printing `promoted <path>` per path.

## Requests to core

- **R1, `Files` binary I/O:** `Files` has `readText`/`writeText` only (and no `copy`, `mkdir` or `stat`), so promotion
  compares and copies through `cmp` and `cp` on `ProcessRunner`. With `readBytes`/`writeBytes` (already requested
  by M3.8a's D7) the copy would go through `Files`.
- No request for the evidence schema: promotion reads three fields with its own reader, and the contract test keeps
  the reader in step with core's schema.

## Decisions for the Owner's review (defaults in effect; each can be vetoed)

- **DT-D1, nothing to import.** `exports: {}` makes every resolver (Node, Vite, any bundler that honours `exports`)
  refuse the package name, so a game cannot bundle it even by mistake; the bins are the only surface.
- **DT-D2, `--to` is required** for `promote-evidence`; a game names its baseline folder in its own script.
- **DT-D3, "running process" means a process whose working folder is inside the worktree** (`lsof`); a process that
  only holds a file open there is not seen. When `lsof` is missing or fails, every worktree is kept.
- **DT-D4, orphans are never removed** by the tool.
- **DT-D5, the bins run from source** under Node's type stripping, so imports keep `.ts` (as `tooling/pipelines`).
  Publishing the package needs a build first (Node does not strip types under `node_modules`), as every Plus package does.
- **DT-D6, `evidence.json` is checked when promoted** (clean tree, every golden's engines agree), so a committed
  evidence file never claims what its run did not prove.

## Review round 1 (decisions for the Owner's review)

- **DT-D7, ignored files hold a worktree.** `git worktree remove` deletes ignored files even without `--force`, and
  plain `git status` hides them, so `worktree-gc` reads `git status --porcelain --ignored` and keeps a worktree with
  any ignored path outside the regenerated folders, naming the paths. The allowlist, matched as a whole path segment
  anywhere: `node_modules`, `.turbo`, `dist`, `.core`, `.evidence` (core's per-package golden reports),
  `playwright-report`, `test-results`.
- **DT-D6 (amended), promotion needs provenance.** Every selected file's run must have an `evidence.json`: the nearest
  one above the file inside the evidence folder, else the one core's collector writes at the repository root. A
  missing, dirty or disagreeing one refuses the whole promotion. So a screenshot-only game must run core's collector
  (or place an `evidence.json` beside its set) before promoting.
- **DT-D8, containment.** `--from` and `--to` must be relative without `..`; `--to` must resolve inside the
  repository; a target that is a symlink, or whose folder resolves outside `--to`, is refused. The real paths come
  from `node:fs` (`realpath`, `lstat`) in `src/real-path.ts`, because `Files` has neither (request **R2** to core).
