## Scope

In (`packages/debug`, the first Svelte package in Plus; presentation only: no sim entry, no golden, no `boundaries` row):
- **The gate:** a `debugBuild(debug)` Vite plugin (`@mcthaydt/automata-debug/vite`) that defines `__AUTOMATA_DEBUG__` (true in dev, or in a
  build made with `--debug`; false otherwise). Every debug module is reached only through `if (__AUTOMATA_DEBUG__)`, so a release build
  tree-shakes the overlay and the driver.
- **Panels:** `DebugPanelDef`, `debugPanels(...)` (validates kebab-case unique ids with titles) and `debugExtension`, which fills
  `hud.overlay` with the overlay. The `debug.panels` slot is not used (DBG-D1).
- **The host:** `installDebug(host)` takes the handles panels read (`DebugHost`: bus, optional sim probe, optional feel, optional pause,
  optional state and click for the driver). Panels read it through Svelte context set by the overlay, never props.
- **The overlay:** a controller (open, close, tab, backquote, three-finger tap, Escape) and `DebugOverlay.svelte`: tabs for every panel
  in a scroll region, a "pause sim" toggle, one panel's error shown in its tab while the others keep working.
- **Panels shipped:** sim (tick, entities, last hash, step time), presentation bus (last 50 facts), feel board (fire any entry).
- **The driver:** `window.__automataDebug` (`state`, `click`, `floor`, `facts`) installed by `installDebug` and removed by its dispose.
- **DB-a** (jsdom: the overlay opens on the dev key and lists every registered panel) and **DB-b** (a Vite build of a fixture: the
  release bundle has neither the overlay marker nor `__automataDebug`; the dev build has both).

Out: the audio board (M6.10b), per-extension panels (puzzle, agents, dialogue, nav: each extension's own row), the one-file example
`debug/debug-panel.ts` (Plus has no examples runner yet: EX.4p), the `automata build --debug` flag itself (core's CLI; the plugin takes
the boolean), `?debug&carry=` start options (a game concern), real-browser layout runs (no phone-size layout row in this slice).

## Decisions for the Owner's veto

- **DBG-D1:** core renders no `debug.panels`, gives slot components no services context, and an extension fills a slot with one
  component, so it cannot carry several titled panels. No core change: `debugExtension` fills `hud.overlay` with the overlay, each
  extension exports its `DebugPanelDef`s, the game hands them with the host handles to `installDebug`, and panels read the host
  through Svelte context. A services context in core would replace this later.
- **DBG-D2:** the build constant is `__AUTOMATA_DEBUG__` set by a Vite plugin, not `import.meta.env.DEV` alone, so `--debug` release builds
  work; the plugin takes `debug: boolean` and the game's config passes `mode !== 'production' || flag`.
- **DBG-D3:** the driver is generic (`state`, `click`, `floor`, `facts`) over handles the game gives; the adventure source's
  game-named methods stay in that game.

## Execution log

- Svelte tooling is new to Plus: the package carries its own devDependencies (vite-plugin-svelte, Testing Library, jsdom, svelte-check,
  TypeScript 6 for svelte-check, which does not run on TS 7). Biome got a `*.svelte` override (it cannot see template usage).
- `sideEffects` is `false` (not `*.svelte`) so Rollup drops the debug imports behind the gate; the bundle test proves it, and a
  fixture that forgets the gate fails the marker check.
- The panels (step 4) and the overlay (step 3) tests were written in the same edit as their components; they failed first on the
  missing module. The shipped panels sit in `src/panels/`; `feelBoard` adapts `Feel` and the content to the board port.
- Not done (out, listed above): audio board (M6.10b), extension panels, example `debug/debug-panel.ts`, real-browser layout, `automata build --debug`.
- Gates: package tests, svelte-check, biome, Plus `pnpm check`. No golden, no changeset (private), no parity project.
