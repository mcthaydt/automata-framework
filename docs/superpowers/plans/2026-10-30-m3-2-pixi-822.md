## Why

`@pixi/3d` 0.1.0-beta.2 (vendored in `vendor/pixi-3d/`) declares the peer `pixi.js` `^8.22.0`; core pins 8.21.0. The 3D runtime (M3.4 and on) cannot install against core until core moves. The spec makes the bump its own task with every gate (risk table: "The 8.22 bump changes 2D behavior"), before any 3D code depends on it.

## S7-Q6 answer

**Does `pixi.js` 8.22 change anything AF depends on? No.** Every gate below is green on 8.22.0 with no golden, layout contract or journey changed (V-a holds).

The 8.21.0 → 8.22.0 diff of `node_modules/pixi.js/lib` (44 changed `.mjs` files; the GitHub release notes were not reachable from this sandbox, so the code is the evidence; npm published 8.21.0 on 2026-09-17 and 8.22.0 on 2026-10-01):

- **Filter stack (`filters/FilterSystem.mjs`), the code path of FloorFifty's guard.** 8.22 rewrites the stack walk. In 8.21, `generateFilteredTexture()` pushed a stack entry and never popped it (nor on its two early returns), so each call left the stack one deeper; `_getPreviousFilterData()` returned a skipped entry when no live one existed; `_findFilterResolution()` never looked at index 0. 8.22 pops on every path, replaces the three walks with `_findClosestFilterData()` / `_getPreviousFilterData()` that return the nearest non-skipped entry or `null`, and drops the unused per-entry `globalFrame` (the `uGlobalFrame` uniform AF's programs declare is still written). This is the class of bug a "filter stack resized during a renderer resize" guard works around, and 8.22 fixes it at the source. AF's own use is a single filter level (the composite stage's or the scene's `filters`, `render-pixi` `renderer.ts`, `letterbox/composite-target.ts`): for one level, 8.21 and 8.22 compute the same resolution (the root's) and offset (0), so AF's output does not move, which the parity goldens confirm.
- **Guard: not extracted (drop).** AF carries no equivalent of FloorFifty's `filter-stack-guard.ts` (no `filter-stack`, `filterStack` or `_filterStack` in `packages/`, `games/`, `examples/`, `tooling/`, `spikes/`). FloorFifty is not reachable from this session (no clone; GitHub access to `SNEKPRTY/FloorFifty` not enabled), so its guard's exact trigger was neither read nor reproduced here, on 8.21 or 8.22. No AF journey or parity case resizes the renderer while filters are on (the journeys start at a fixed phone viewport; `composite-target.test.ts` resizes the target in Node only), so the gates cannot reproduce it either. §4.5 keeps the guard only if the crash reproduces on 8.22; it has not, and the stack leak that such a guard works around is fixed upstream, so the guard is not extracted. Open for the Owner: confirm against FloorFifty's `filter-stack-guard.ts` (`ac72660`) that its trigger is the `FilterSystem` stack walk 8.22 rewrites. If `post-retro` (M3) later stacks nested filters and hits a resize crash, the crash is reproduced on 8.22 first.
- **Resize path otherwise.** `ViewSystem` no longer passes the renderer's `depth` flag into the canvas texture options (it only reaches the root render target, as before); `RenderTargetSystem` and the GL/GPU render-target adaptors add 3D-texture layers and a WebGPU MSAA restore pass. None changes a 2D WebGL2 frame.
- **no-eval.** The five allowlisted generator and probe files are byte for byte the same; `unsafe-eval/ubo/generateUboSyncPolyfill.mjs` fixes the stride of WGSL uniform arrays (a WebGPU fix; AF's filter uniforms are scalars and vectors).
- **Other changes AF does not use or that do not change behavior:** 3D textures and `Gpu3dMipmapGenerator` (for `@pixi/3d`), `TextureSource` `dimensions` deprecated (AF never passes it), `TilingSprite`'s doc default, and a new `contextmenu` federated event (no `preventDefault`, so the browser behaves as before).
