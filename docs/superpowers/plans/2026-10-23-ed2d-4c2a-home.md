ED2D.4c1's table put the scaffold, Home and the open-flow dialogs in one "4c2". Together they are too much to review, and the dialogs are not needed to prove the scaffold. So:

## Decisions made here (written into the 2D spec in this PR)

1. **Logic is headless, components are thin.** `home-model.ts` and `home-controller.ts` run in the Node `unit` project; the controller exposes the Svelte store contract (`state.subscribe`), which a component reads as `$state`-style `$store` and Node tests read directly. The `dom` tests cover what a person sees and does; they do not re-test the logic.
2. **Home is the shell with no rail.** `panel` is the sources panel, `canvas` holds the search, the project list and the templates in one scroll region of its own (`data-scroll-region`, `touch-action: pan-y`, since the shell's canvas takes every gesture), `inspector` is the selected project's summary, `status` is the kit's `StatusLine`. In `medium` and `compact` the panel and inspector are the shell's drawers and sheets; selecting a project opens the inspector (its actions live there), and a top-bar button opens the sources panel.
3. **Projects are a listbox.** One tab stop; arrows (left and right, up and down alike), Home and End move the selection in list order; Enter and double-click open it. Cards do not depend on the number of grid columns.
4. **Kind badges are generic.** Colour comes from the profile's position in the registry (a fixed list of accent tokens), never its id (G-s). Templates are every profile's templates; each carries its profile's label as a tag when more than one profile is registered.
5. **The summary is the profile's.** `Profile.summary?(value): { title, facts }` (optional, so a profile without it still lists: the file name and the counts of errors and warnings are shown). `title` is the document's own name. The app never reads a document's fields.
6. **Import takes any file and keeps the ones a profile claims.** `importFile` reads the bytes with `readDocument`: `parsed`, `invalid` and `choose` files are written (an invalid file is kept so the error panel of 4c2b can show it); `unrecognised`, `notText` and `tooLarge` are refused and nothing is written. A taken name gets ` 2`, ` 3` (the numbering of `create`).
7. **Delete asks once.** A dialog says what goes ("the file and its autosave") and has the destructive action named, not "OK". Duplicate and Import report with a toast that names the new file. Open and New go straight in.
8. **Time is injected.** The "modified" label is relative to `clock.now()` ("just now", "5 min ago", "2 h ago", "yesterday", then the date `Oct 21`), computed in `home-model.ts`, so tests set the clock.
9. **Boot is a function of its environment.** `startEditor(target, env)` takes the window, document, storage and crypto it uses, opens the workspace, builds the registry, ids and app, mounts `App`, and returns a disposer. `main.ts` is the only file that reaches for the globals.
10. **The document frame is a placeholder and says so.** It shows the project's title, a Back button, the save state in the status line, and "The editor views arrive with ED2D.4c4". It exists so Open and New end somewhere real; 4c4 replaces it.

## Contract

```ts
// profiles/profile.ts (additions; both optional)
export interface ProfileSummary {
  readonly title: string                                              // the document's own name
  readonly facts: readonly { readonly label: string; readonly value: string }[]   // in order: Levels 5, Layers 4
}
interface TemplateDef<V> { readonly hint?: string }                  // "side view", "maps · NPCs"
interface Profile<V> { summary?(value: V): ProfileSummary }

// app/project-list.ts: the ok entry gains `summary: ProfileSummary | undefined`

// app/editor-app.ts (addition)
export type ImportOutcome =
  | { status: 'imported'; name: string; path: string }
  | { status: 'refused'; name: string; reason: 'unrecognised' | 'notText' | 'tooLarge' }
  | { status: 'failed'; name: string; reason: StorageFailure; message: string }
// EditorApp.importFile(name: string, bytes: Uint8Array): Promise<ImportOutcome>

// app/home/home-model.ts (pure)
filterProjects(entries, query): readonly ProjectEntry[]     // case-insensitive over path, title and profile label; empty query keeps all
reconcileSelection(visible, selected): string | undefined    // kept if still visible, else the first, else undefined
stepSelection(visible, selected, key): string | undefined    // ArrowLeft/Up back, ArrowRight/Down forward (no wrap), Home, End
modifiedLabel(mtime, now, timeZone?): string
entryBadge(entry): { tone: 'ok' | 'warn' | 'bad' | 'neutral'; text: string }   // Valid, 1 warning, 2 errors · 1 warning, Can’t open, Choose a profile
kindTone(registry, profileId): string                       // the accent's CSS variable, by registry position
templateCards(registry): readonly { profileId; profileLabel; id; label; hint: string | undefined; tagged: boolean }[]
storageNotes(workspace): readonly { tone: 'ok' | 'warn'; text: string }[]
openProblem(outcome): string                                 // the one-line message for each non-opened outcome

// app/home/home-controller.ts
export interface HomeState {
  readonly phase: 'loading' | 'ready' | 'unavailable'
  readonly entries: readonly ProjectEntry[]
  readonly visible: readonly ProjectEntry[]
  readonly query: string
  readonly selected: string | undefined
  readonly busy: 'open' | 'create' | 'duplicate' | 'remove' | 'import' | undefined
  readonly message: string | undefined                       // why the list is unavailable
}
export interface HomeController {
  readonly state: { subscribe(run: (state: HomeState) => void): () => void }
  refresh(): Promise<void>
  search(query: string): void
  select(path: string): void
  step(key: StepKey): void
  open(path?: string): Promise<void>
  create(profileId: string, templateId: string): Promise<void>
  duplicate(): Promise<void>
  remove(): Promise<void>
  importFiles(files: readonly { name: string; bytes: Uint8Array }[]): Promise<void>
}
export function createHomeController(options: {
  app: EditorApp; toasts: ToastStore; onOpened(opened: Extract<OpenOutcome, { status: 'opened' }>): void
}): HomeController
```

## Component and state inventory

| Component | States it must show |
|---|---|
| `SourcesPanel` | "This workspace" with the project count and where it lives (browser storage, or "this session only" when `persistent` is false); the storage notes (autosave on, persistent storage, or the kit's reason in a warning tone); Import files…. Folder is absent (decision above) |
| `ProjectList` / `ProjectCard` | loading skeleton; list; empty workspace ("No projects yet"; the templates are right below); no search match ("Nothing matches 'x'"; Clear); selected; focus ring; per-card badge (Valid, n warnings, n errors, Opens with problems, Needs a profile); the profile's tone and label; the file path (middle-truncated); size; modified label |
| `TemplateRow` | one card per template of every registered profile, the profile tag when two or more profiles exist; busy (disabled, not hidden) while a document is being made |
| `ProjectSummary` | nothing selected ("Select a project"); ok (title, facts, badge, Open, Duplicate, Delete); broken (the first reason, Open still offered: 4c2b shows the error panel); ambiguous (the candidates, Open); busy |
| `DeleteDialog` | open; confirm names the file; Delete (destructive) and Cancel; focus returns to the list; Escape cancels |
| `UnavailableNotice` | the list cannot be read (the kit's message), Retry |
| `DocumentFrame` | the title, Back, the save state, the placeholder body |
| `ToastRegion` | duplicate, import, delete and open problems |

Responsive and input: wide 1194×834, 1366×1024 and desktop (inline panel, canvas, inspector); medium 834×1194 and 1133×744 (the panel and inspector are drawers, the project list and templates are the whole width, the inspector opens on selection); compact 390×844 (sheets, one column, same actions). Touch targets 44, primary actions (Open, New) 48. Finger: tap selects, a second tap on the selected card or the Open button opens, scroll pans the list. Pencil: as finger. Mouse: hover shows the card's border, double-click opens. Keyboard: Tab reaches search, list, templates and summary in that order; arrows move the selection; Enter opens; Delete (with the list focused) asks to delete; Escape clears a non-empty search, else closes a drawer. Nothing is hover-only. Rotation keeps the selection, the search text and the scroll position (the shell keeps every region mounted).

## Failure and recovery

| Failure | Behavior |
|---|---|
| The workspace cannot be listed | Phase `unavailable`: the message and Retry; the sources panel and templates stay usable |
| One file cannot be read | Its card is `broken` with the reason; the rest list (4c1) |
| Open or New returns anything but `opened` | A toast with the outcome's message (4c2b: the proper panel); the list is refreshed |
| Create hits a full disk | `storageFailed`: toast with the reason; nothing is written |
| Duplicate, Delete or Import fails | A toast with the reason; the list is refreshed; the selection is kept when its file still exists |
| A file is deleted from under the list | Open says `missing`: toast and refresh |
| Import of a file no profile claims | Refused with a toast naming the file and why; nothing written |
