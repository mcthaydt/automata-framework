# M1.4 Host: implementation plan

> Steps use checkboxes. Tick each one when its check passes and commit the tick with that step's work.

**Goal:** Build `@mcthaydt/automata-host` as the [M1.4 host spec](../specs/2026-10-11-m1-host-design.md) describes. That means the `Hosting` Effect service, its typed errors, the Ruken, web and auto layers, the `./testing` layers, and the ported FloorFifty and S6 tests.

**Progress:** 3 of 9 tasks.

**Tech stack:** Node 24, pnpm 10.33.4, TypeScript 7.0.2, Vitest 5.0.3, Biome 2.5.15. The root config already pins all of these. This package adds `effect` 3.22.2 (the repo-wide choice, §Deviations), the vendored `@ruken/sdk` and `@ruken/sdk-host` (RukenApp `b30d31b`), and `jsdom` 30.1.2 for DOM tests.

**Consumed interfaces:**
- `@ruken/sdk`: `Ruken.init`, `RukenSession`, `RukenError`, `SdkEnv`, and the re-exported protocol types.
- `@ruken/sdk-host/testing`: `createFakeHost`, `FakeHost`, `FakeHostOptions`, `settle`.

**Produced interfaces:** spec §3.

## Tasks

Each task follows the same loop: write the failing test, run it, see it fail for the stated reason, add the least code that passes, then run `pnpm --filter @mcthaydt/automata-host test`.

### Task 1: vendor Ruken and set up the package
- [x] Pack `@ruken/sdk` and `@ruken/sdk-host` from RukenApp `b30d31b` (`pnpm run build` in each package, then `pnpm pack`). Copy them to `vendor/ruken/` and record the commit and SHA-256 in `vendor/ruken/sdk.md`.
- [x] Create `packages/host` with `package.json` (`@mcthaydt/automata-host`; `effect`, `@ruken/sdk` and `@ruken/sdk-host` as `file:` tarballs; `jsdom` and `vitest` as dev dependencies), `tsconfig.json` and `vitest.config.ts` (node project, with jsdom per file).
- [x] Smoke test `src/vendor.test.ts`: with the fake host, `Ruken.init` reaches `hosted: true`. Before the install it fails because the module can't be resolved; after the install it passes.

### Task 2: errors
- [x] `errors.test.ts`: `toHostError("saves.flush", new RukenError("TIMEOUT", …))` returns `HostRequestFailed { operation, code: "TIMEOUT", retryable }`, and a `DENIED` error returns `CapabilityDenied`. The test fails first because the module is missing.
- [x] Implement it.

### Task 3: rounds guard
- [x] `rounds.test.ts`: an end with no round open is dropped; a second start is dropped; start, then end, then end gives one start and one end (FloorFifty `hosting.test.ts`, the last case).
- [x] Implement `guardRounds`.

### Task 4: Ruken adapter, handshake and readiness
- [ ] `ruken.layer.test.ts`. A fake host gives `kind: "ruken"`, `hosted: true` and the granted capabilities. With `autoReady: false`, `ready` waits for `markReady`. A frame that never welcomes (`env` with no host) gives `HostHandshakeFailed` after 10 s on fake timers, with no web fallback. A forged self-welcome is ignored, and so is a second welcome.
- [ ] Implement `session-hosting.ts` (readiness and identity only) and `RukenHostingLive`.

### Task 5: saves
- [ ] `saves.test.ts`. The snapshot is readable. A write sends `saves.set` with the key and value. `flushSaves` succeeds. Without the `saves` grant, `saves` and `flushSaves` fail with `CapabilityDenied` and nothing reaches localStorage. A flush that times out gives `HostRequestFailed { code: "TIMEOUT" }`. The shared limits suite (key regex, 1 MiB, 10 MiB counted as UTF-8 key plus value, 256 keys, cache unchanged after a refusal) runs against both adapters. `deviceStorage` is separate.
- [ ] Implement it.

### Task 6: display, audio, lifecycle, fullscreen
- [ ] `display.test.ts`. Fullscreen is asked of the host and reports `ios-home-screen`. `display` and `displayChanges` follow the host. `hostReserved` gives the width on its own side and zero on the other, and follows changes. `audioGain` follows master volume and ad ducking. Lifecycle reports `background` for `hidden` and `host-overlay`, then `active`.
- [ ] Implement it.

### Task 7: menu, exit, links, ads, analytics, rounds
- [ ] `services.test.ts`. The menu stays refused until a handler is set, and then the handler's answer goes back. `menu.open` before ready answers `NOT_READY` without calling the handler. `exit("player")` sends `session.exit`. `onExiting` work runs before the host closes, is cut at 1 s, and is removed when its scope closes. Links go through the host, and a link without the grant gives `CapabilityDenied`. The natural break resolves when the ad is shown, fails or is too early; a rate-limited break gives `HostRequestFailed { code: "RATE_LIMITED" }`. `track` sends disclosed events with consent, sends nothing without consent, and drops undisclosed names. Rounds go through the guard.
- [ ] Implement it.

### Task 8: web adapter and `HostingLive`
- [ ] `web.layer.test.ts` (jsdom). It gives `kind: "web"` and `ready` at once. Saves go to `ruken:<gameId>:` keys and pass the shared limits suite. Fullscreen uses `requestFullscreen` and gives `support: "element"`, or `"none"` when the API is missing. Links are https only and open with `window.open`. Lifecycle follows `visibilitychange`. `naturalBreak` gives `CapabilityDenied("ads")`. `exit` succeeds. Listeners are removed on scope close. `HostingLive` picks `web` at top level and `ruken` in a frame. `test-host-origin` cases: a listed origin is accepted, no listed origin drops the welcome, and any other origin drops it.
- [ ] Implement it.

### Task 9: testing layers and the local gate
- [ ] `testing/testing.test.ts`. `FakeRukenHosting` provides `Hosting` and `FakeHostHandle` (with `sentByGame`). `RecordingHosting` records breaks (which wait for `endBreak`), rounds through the guard, tracks, exits and links, and `emitLifecycle` reaches subscribers.
- [ ] Implement it.
- [ ] Run `pnpm format`. On Node 24, `pnpm check` is green and the sim parity suite passes in Chromium, WebKit and Firefox. Record the summary lines in the execution log and the PR.
