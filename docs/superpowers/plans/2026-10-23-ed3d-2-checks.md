## Why this task exists

The editor refuses nothing the format allows, but it must say, after every step, what is wrong with the level and where. Last Light's `validate` (`scripts/pipeline/blockout-lib.ts`) does that for its own files by binding the game's engine modules and printing a sentence per problem. The editor needs the same rules as pure functions that return *where* each problem is (a selection id and a point) so Locate can frame it, and it needs the rules that are not Last Light's (a sector overlapping another, a ceiling below its floor) to run on any profile. ED3D.1c made the geometry queries pure; this task puts the rules on them.

```ts
export type Severity = 'error' | 'warning'
export interface Locator { readonly selection: string; readonly at?: Point | undefined }   // `sector:hall`, `wall:hall/4`, `entity:box/desk`
export interface Problem { readonly message: string; readonly locator?: Locator | undefined }
export interface CheckResult {
  readonly id: string                     // `ids`, `shared-walls`, `openings`, `overlap`, `heights`, `expand`, `rooms`, `puzzle-hotspots`, `nav`
  readonly ok: boolean                    // no problems
  readonly severity: Severity
  readonly detail: string                 // the problems joined by "; ", or the ok text: Last Light's own `detail`
  readonly problems: readonly Problem[]
}
export interface GeometryContext { readonly map: ResolvedMap; readonly wall: (edge: Edge) => Locator }
export function genericChecks(context: GeometryContext): CheckResult[]           // shared-walls, openings (portals), overlap, heights
export interface LastLightOptions { readonly puzzleHotspots?: readonly string[] | null }   // null or absent: the level has no puzzle
export function lastLightChecks(blockout: Blockout, options?: LastLightOptions): CheckResult[]
```

Rules for the port: a problem's `message` is Last Light's sentence unchanged (so `detail`, the messages joined by `; ` with duplicates dropped as `ids` does, equals Last Light's `detail`); what is added is the locator. Last Light's result ids lose their `blockout:` prefix. The order and short-circuits are Last Light's: a document that does not expand returns only `expand`; one whose rooms do not resolve returns `ids` and `rooms`; otherwise `ids`, `shared-walls`, `openings`, `puzzle-hotspots`, `nav`, with the two new generic results `overlap` and `heights` after `openings`.

**Locators.** Selection ids are the spec's (§4.1): `sector:<id>`, `wall:<sector>/<corner index>` where the index is the document's corner the wall starts at, and `entity:<definition>/<id>` with Last Light's fixed definitions `spawn`, `box`, `hotspot`, `lamp`, `anchor`, `node`, `zone`. An expanded edge is not always a document corner (`expand` splits a wall at an opening and adds a connector sector; a pilaster adds notch walls), so `wallLocator(blockout)` finds the corner whose segment holds the edge's midpoint, and gives `sector:<id>` for a connector, a hole or a pilaster notch. The `at` point is the problem's own: a wall's start, a node, a hotspot.

**Overlap and heights are new rules, not ports**, so they have no golden; their evidence is seeded violations, and that the four shipped blockouts pass (the source test "sectors do not overlap" already says they should).

## Risks and how the plan answers them

- **A port that drops a rule.** The golden is Last Light's own `validate` over the shipped files and one case per problem sentence, compared on `id`, `ok` and `detail`, so a dropped or reworded rule shows up as a different result.
- **Last Light's `validate` is not runnable as it stands.** It binds the game's engine modules through dynamic imports and reads `src/render/look.ts`. The recorder builds a scratch copy with explicit extensions, an empty `look.ts` and stub scene files (as the ED3D.1c recorder does), passes the puzzle list in `opts.puzzle` so no scene module is imported, and reads the checkout without writing to it.
- **Locators that point at the wrong wall.** The corner a wall came from is found by geometry and tested on split walls, connectors, holes and notches; a wall that cannot be placed falls back to its sector, never to a wrong corner.
- **Overlap false positives on legitimate layouts** (rooms that touch, holes, steps). The rule is tested on touching, nested and holed layouts and must pass all four shipped blockouts before it is turned on.
