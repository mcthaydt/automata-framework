## What is wrong

`pnpm-workspace.yaml` overrides `zod` to 4.6.6 for the whole workspace because the vendored `@ruken/cli` and `@ruken/sdk-host` tarballs (packed from RukenApp `b30d31b` on 2026-10-11) declare `zod` 4.6.5 exactly, which GHSA-mrhx-c7xc-m3w5 covers. At RukenApp `main` (checked at `d0fa2fe766d532a293c3723d5ba3102d1e602d63`, 2026-10-28 09:31 -05:00), `@ruken/sdk-host` and `@ruken/cli` declare `zod` 4.6.6 (the SDK only as a dev dependency; `@ruken/manifest` does not use zod), read from the packed `package.json`s. Repacking from there lets the override go. (Corrected in step 7: the first draft said all four packages declare it.)

## Decisions

- **Repack in a scratch clone**, never in `/home/user/rukenapp`: `git clone --depth=1 https://github.com/mcthaydt/rukenapp` into the session scratchpad, `pnpm install --frozen-lockfile`, then `vendor/ruken/README.md`'s recipe (each package's own `pnpm run build`, then `pnpm pack`). Ruken's `turbo run build` still needs a database for `@ruken/db#db:generate`, and these four packages do not.
- **Drop the override and its comment** from `pnpm-workspace.yaml`. `docs/versions.md`'s `zod` row never named the override (QB.1e changed only its version); the stale cross-reference was the override's own comment, which goes with it.
- **Pin the new trusted host origins in a host test**, as `saves.test.ts` pins the SDK's ungranted-write behaviour: a re-vendor that changes which hosts the SDK trusts shows up in AF. The origins are written in the test (a fixture), not exported or redefined by AF.
- **Keep `Hosting.leaderboards.get`, undeprecated,** and correct its doc comment to say what Ruken answers now. Moving AF's board screens to Ruken's achievements is product work for its own milestone (follow-up).
- **Re-check every comment that cites the vendored SDK at `b30d31b`** in `packages/host` and `packages/ship` (`sdk-markers.ts` asks for it) and move the commit to `d0fa2fe` where the claim still holds; provenance notes of code ported from Ruken at `b30d31b` stay as they are (history).
- **One patch changeset** for the published packages whose published files change with the repack: `content`, `host` and `ship` bundle Ruken code, and `ui` inlines every SDK type into `dist/vendor/ruken-sdk.d.ts`, which gains the `@deprecated` note on `leaderboards.get`, `RewardedAdRes` and `RukenSession.ads.rewarded()`. `testing` was named in the first draft and dropped in step 7: it inlines only `DisplayMetricsPayload` (unchanged), a forced build gives a byte-identical `dist/`, and its `files` is `dist` alone. `cli` bundles `@ruken/manifest` too but is private, so it is not named.
- **Make turbo's build cache key cover `vendor/ruken/`** (step 7). The lockfile key of a `file:` tarball (`@ruken/sdk@file:vendor/ruken/…@0.0.0`) does not change when the tarball is repacked, so packages with no source change in this PR (content, testing, ui) replayed `main`'s b30d31b builds from the shared turbo cache. `turbo.json`'s `build.inputs` gains `$TURBO_ROOT$/vendor/ruken/**`, beside `tooling/release/src/**` and for the same reason (write-vendored reads `vendor/ruken/README.md`; the build bundles the tarballs).
