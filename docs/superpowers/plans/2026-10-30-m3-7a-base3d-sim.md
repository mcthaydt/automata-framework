## Why

The base 3D game needs a deterministic sim before it gets a picture: a character who walks relative to the camera, a camera heading the player turns, two rooms whose views cut at a doorway without reversing the stick, and a lock target. That sim is what B-a holds identical in Node, Chromium, WebKit and Firefox, and what M3.7b's renderer, screens and figures read through render rows.

## Scope

In: the sim plugin (hero, targets, wall boxes, rooms with views, `move`, `lock`, the reused `camera-heading` plugin); the first slice's two-room area as content; the golden replay in four engines with its evidence; a minimal page (`defineGame` with the default screens and the keys for `move`) so the package builds and prepares for Ruken; the game-ci job, the root boundaries root, `ci:local` and the evidence list.

Out (later rows): the renderer, figures, clips, GLB props, fog, occluders, the touch and pad mapping, `camera-turn` and `lock` input bindings (M3.7b, GAME-3D.1h); the lock selection cone, cycling, assist and break rules (GAME-3D.1b); combat and everything else in the design doc.

## Decisions (agent defaults, for the Owner's veto)

1. **Package `@af-games/base-3d`**, `private: true`, in `games/base-3d` (the design doc §2 names it; Emberwick kept `@af-examples/base-2d`).
2. **EsperRedux flat layout (GAME3D-D21), sim files only in `src/`.** `src/constants.ts`, `components.ts`, `commands.ts`, `systems.ts`, `state.ts`, `content/first-slice.content.ts`, `game.test.ts`. No `events.ts` yet: the first slice's sim emits nothing a reader needs (the renderer reads `view` from the rows), so an empty role file would be speculative. **`main.ts` sits at the package root, as Emberwick's does**, not in `src/`: `pnpm boundaries` can only check a folder whose every file is sim code (finding 1), so `src/` stays all sim until the tooling learns the flat layout (GL.1).
3. **Fixed point is Q16.16 metres** (65,536 to a metre), the stick mapper's unit, so a mapped direction times a speed is one integer product. Facing and `moveDir` are turn units (65,536 to a turn, the heading's unit): `facing` in 0..65,535, `moveDir` signed in −32,768..32,767 (0 forward, ±16,384 strafe, −32,768 backing away). The renderer converts to metres and radians (M3.7b).
4. **Walk speed 4 m/s at full push**, scaled by the stick's length (the mapper's output); per tick `trunc(direction × 4,369 / 65,536)` (4,369 = round(4 / 60 × 65,536)). A tunable until `content/tuning.toml` (GAME-3D.1k).
5. **The hero collides as a square of half-size 0.3 m** (the design doc's hurt radius) against axis-aligned wall boxes in plan, one axis at a time (x then z), clamped to the box face, so a move of at most 0.07 m a tick never passes a 0.2 m wall. A box the hero already overlaps does not push.
6. **Rooms are plan boxes naming a `camera-view`.** The hero is in the first room (content order) whose box holds its position (min inclusive, max exclusive); outside every room the view stays. Entering a room calls `enterView` (M3.4b) with this tick's stick, so a held stick latches. The view system runs after the move (`postPhysics`), so the latch applies from the next tick's move.
7. **Minimal lock (§4.7: "a held action sets `lockTarget`").** `lock { down }`; on the press, the nearest target within 12 m in plan (squared Q16 distances, ties to the lower entity id) becomes `lockTarget`; while held it stays; release clears it. While locked, `facing` turns toward the target (`atan2` from `dmath`, rounded to a turn unit) and `moveDir` is the travel angle minus the facing. The cone, cycling, assist and break rules are GAME-3D.1b's.
8. **The golden route drives commands directly** (`move` sticks, `camera-turn` units, `lock`), not key presses: the input mapping is M3.7b's. It covers a walk, a camera turn (one past the clamp), the doorway with the latch held and released, a wall, a lock and a strafe.
9. **The page** is `defineGame({ id: 'base-3d', sim, input: keys(Move, WASD/arrows → ±127), content: { ...defaultContent(), sim: area } })` with the default screens and no renderer, landscape (§4.7). It exists so game-ci can build and prepare the package; M3.7b replaces it.

## Steps

Each step: write the failing test, run it and confirm the failure reason, make the minimal change, run it green.

- [ ] **1. Package and a plugin that registers.** Test: `createSim({ plugins: [cameraHeadingPlugin, base3dPlugin] })` succeeds and the hash is a 16-hex string. Fails: no module. Then package.json, configs, empty plugin. `pnpm --filter @af-games/base-3d test:unit`.
- [ ] **2. The area compiles.** Tests: metres become Q16 integers; a room naming an unknown view, a wall whose min passes max and an unknown field each throw; the first slice compiles. Fails: no `compileArea`.
- [ ] **3. Setup places the hero.** Tests: after `BASE3D_SIM.setup`, the hero is at the spawn, in the spawn room's view with its yaw as the heading and no latch, and one target exists. Fails: no setup.
- [ ] **4. The stick moves the hero relative to the camera.** Tests: stick up at heading 0 moves +z by 4,369 a tick; at heading 16,384 it moves +x; a keyboard diagonal is no faster than straight; `facing` follows travel; `moving` is set and cleared; `moveDir` is 0 while unlocked. Fails: no `move` command or system.
- [ ] **5. Walls stop the hero.** Tests: walking into a wall stops flush at the face minus the half-size and never passes it in 600 ticks; sliding along a wall keeps the free axis. Fails: hero walks through.
- [ ] **6. Rooms set the view; the latch holds across the doorway.** Tests: walking from the hall through the doorway enters `kiln` and sets the heading to its yaw on that tick; with the stick held the hero keeps moving +z (latched); after a release, stick up moves along the new heading; a turn lets go of the latch. Fails: view never changes.
- [ ] **7. `camera-turn` reaches the hero's heading.** Tests: a turn of 1,000 turns the heading and the mapping; 10,000 is clamped to 8,192; a `rotate: false` view ignores it (a test area). Fails only if the plugin is not wired; confirm by running before wiring the dependency.
- [ ] **8. Lock.** Tests: a press picks the nearest target in range (tie to the lower id, none past 12 m); while held, `facing` points at the target and stick right gives `moveDir` 16,384 ± 1 at several headings; release clears `lockTarget`. Fails: no `lock` command.
- [ ] **9. Golden replay (B-a).** Test: the scripted route ends on the recorded hash, rejects nothing, enters `kiln` on the recorded tick, and replays twice to the same hash; the same file runs in the browsers project (Chromium, WebKit, Firefox) and records `@mcthaydt/evidence` for `base-3d/golden-route`. Record the hash in Node first (the test fails on a placeholder hash with the real one), then `pnpm --filter @af-games/base-3d test:parity` must pass unchanged in all three browsers.
- [ ] **10. Page, ship config and game-ci wiring.** Tests: `ship-config.test.ts` (id `base-3d`, landscape, webgl2, manifest passes `checkManifest`); `packages/ship/src/workflows.test.ts` gains: a `base-3d` job through `game-ci.yml` (`working-directory: games/base-3d`, `sim-roots: src`, its own artifact name, the docs-only/draft gating), `ci:local` builds and prepares base-3d, root `boundaries` names `games/base-3d/src`, and base-3d is a golden package with `test:evidence`.
