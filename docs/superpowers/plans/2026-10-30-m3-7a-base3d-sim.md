## Why

The base 3D game needs a deterministic sim before it gets a picture: a character who walks relative to the camera, a camera heading the player turns, two rooms whose views cut at a doorway without reversing the stick, and a lock target. That sim is what B-a holds identical in Node, Chromium, WebKit and Firefox, and what M3.7b's renderer, screens and figures read through render rows.

## Scope

In: the sim plugin (hero, targets, wall boxes, rooms with views, `move`, `lock`, the reused `camera-heading` plugin); the first slice's two-room area as content; the golden replay in four engines with its evidence; a minimal page (`defineGame` with the default screens and the keys for `move`) so the package builds and prepares for Ruken; the game-ci job, the root boundaries root, `ci:local` and the evidence list.

Out (later rows): the renderer, figures, clips, GLB props, fog, occluders, the touch and pad mapping, `camera-turn` and `lock` input bindings (M3.7b, GAME-3D.1h); the lock selection cone, cycling, assist and break rules (GAME-3D.1b); combat and everything else in the design doc.

## Decisions (agent defaults, for the Owner's veto)

1. **Package `@af-games/base-3d`**, `private: true`, in `games/base-3d` (the design doc §2 names it; Emberwick kept `@af-examples/base-2d`).
2. **EsperRedux flat layout (GAME3D-D21), sim files only in `src/`.** `src/constants.ts`, `components.ts`, `commands.ts`, `systems.ts`, `state.ts`, `content/first-slice.ts`, `game.test.ts`. No `events.ts` yet: the first slice's sim emits nothing a reader needs (the renderer reads `view` from the rows), so an empty role file would be speculative. **`main.ts` sits at the package root, as Emberwick's does**, not in `src/`: `pnpm boundaries` can only check a folder whose every file is sim code (finding 1), so `src/` stays all sim until the tooling learns the flat layout (GL.1).
3. **Fixed point is Q16.16 metres** (65,536 to a metre), the stick mapper's unit, so a mapped direction times a speed is one integer product. Facing and `moveDir` are turn units (65,536 to a turn, the heading's unit): `facing` in 0..65,535, `moveDir` signed in −32,768..32,767 (0 forward, ±16,384 strafe, −32,768 backing away). The renderer converts to metres and radians (M3.7b).
4. **Walk speed 4 m/s at full push**, scaled by the stick's length (the mapper's output); per tick `trunc(direction × WALK_PER_TICK / 65,536)`, with `WALK_PER_TICK = round(4 × 65,536 / TICK_HZ)` = 4,369 at 60 Hz. `defineGame`'s sim spec takes no `tickHz`, so the page's sim runs at the sim's default (60 Hz); `TICK_HZ` is that default, `BASE3D_SIM` names no rate, and the page's test asserts its sim steps at `TICK_HZ`. A tunable until `content/tuning.toml` (GAME-3D.1k).
5. **The hero collides as a square of half-size 0.3 m** (the design doc's hurt radius) against axis-aligned wall boxes in plan, one axis at a time (x then z), clamped to the face it crosses. The test is on crossing a face from outside, so no move passes through a wall, however thin. A box the hero already overlaps does not push, which is why `compileArea` refuses a spawn whose square overlaps a wall (touching is allowed) or that lies outside every room.
6. **Rooms are plan boxes naming a `camera-view`.** The hero is in the first room (content order) whose box holds its position (min inclusive, max exclusive); outside every room the view stays. Entering a room calls `enterView` (M3.4b) with this tick's stick, so a held stick latches. The view system runs after the move (`postPhysics`), so the latch applies from the next tick's move.
7. **Minimal lock (§4.7: "a held action sets `lockTarget`").** `lock { down }`; **edge-triggered**: on the press only (`hero-control.lockPressed`, true on the tick `lock` goes down), the nearest target within 12 m in plan (squared Q16 distances, ties to the lower entity id) becomes `lockTarget`, or none; holding keeps that result, so walking into range while held does not lock (review of #250); release, or the target going away, clears it. While locked, `facing` turns toward the target (`atan2` from `dmath`, rounded to a turn unit), kept as it was when the target stands exactly on Wick, and `moveDir` is the travel angle minus the facing (negative is to his right, clockwise seen from above). The cone, cycling, assist and break rules are GAME-3D.1b's.
8. **The golden route drives commands directly** (`move` sticks, `camera-turn` units, `lock`), not key presses: the input mapping is M3.7b's. It covers a walk, a camera turn (one past the clamp), the doorway with the latch held and released, a wall, a lock and a strafe.
9. **The page** is `defineGame({ id: 'base-3d', sim, input: keys(Move, WASD/arrows → ±127), content: { ...defaultContent(), sim: area } })` with the default screens and no renderer, landscape (§4.7). It exists so game-ci can build and prepare the package; M3.7b replaces it.
10. **Flat role-file names stay, against `pnpm style`'s suffix rule.** `node tooling/check-style/src/cli.ts games/base-3d/src` reports three role-suffix findings: `commands.ts` (wants `*.command.ts`), `components.ts` (`*.component.ts`) and `systems.ts` (`*.plugin.ts`). The names follow the Owner's EsperRedux layout (one file per role, GAME3D-D21), and the suffix rule applies inside role folders from GL.1; root `pnpm style` checks only `packages/*/src`, so it does not cover `games/` yet and the gate is green. GL.1b reconciles the rule with the flat layout. The fourth finding was real and is fixed: the area was `content/first-slice.content.ts`, a role suffix for `defineContentSchema` results, which it does not export, so it is now `content/first-slice.ts` (the design doc names no such file).

## Findings

1. **`pnpm boundaries` cannot check the flat layout.** A root given as a file (`games/base-3d/src/systems.ts`) reports every relative import of a sibling sim file as outside its root (`relative(root, target)` starts with `..` when the root is a file), and a folder root checks every file in it. So the flat layout's `src/main.ts` and `src/views.ts` cannot sit beside the sim files and pass. M3.7a keeps `src/` sim-only (the page is at the package root). GL.1 needs the checker to take file roots (resolve against the file's folder) or an exclude list.
2. **`pnpm style` does not check `games/` at all** (`check-style packages/*/src`), so the role-suffix and 600-line rules do not apply to base-3d or Emberwick. Run by hand on `games/base-3d/src` it reports the three flat role files (decision 10), which GL.1b reconciles.
3. **render-pixi3d's camera driver and `pose-3d` read metres and radians** (`x`, `y`, `z`, `yaw`), while base-3d's sim holds Q16.16 metres and turn units. M3.7b's `views.ts` needs a bridge (a render component in metres, or a scale option in the driver: render3d's call).
4. ~~**The runtime never installs an extension's sim plugins**~~ Resolved by RT.EXT1 (2026-10-30): base-3d registers `render3dExtension` and `BASE3D_SIM` names only `base3dPlugin`.
