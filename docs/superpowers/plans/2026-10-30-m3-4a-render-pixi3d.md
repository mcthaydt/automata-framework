## Decisions (agent defaults, for the Owner's veto)

1. **The shim plugs in at the polyfill generators, not the arrays.** `pixi.js` has an `exports` map, so `pixi.js/lib/unsafe-eval/.../uniformSyncFunctions.mjs` cannot be imported by a package; the spike reached it with Vite aliases, which every game's bundler would have to copy. `render-pixi3d/no-eval` instead imports `pixi.js/unsafe-eval` and `@pixi/3d`, then wraps the polyfills `pixi.js/unsafe-eval` installs on the **exported** `GlUniformGroupSystem`, `GlUboSystem` and `GpuUboSystem` (`_generateUniformsSync`, `_generateUboSync`, the same methods `unsafe-eval` itself replaces): a uniform whose first matching parser is one of `@pixi/3d`'s four is uploaded by AF's function for it (the spike's four functions), the rest by pixi's polyfill. No path alias, no consumer config. **The pin test** fails loudly when pixi or the beta moves: pixi's own parser count (5), the total (9), the four 3D parsers' order and types (`mat4x4`, `mat3x3`, `vec3` from `{x,y,z}`, `vec3` from `{r,g,b}`), the two method names, and each AF function's output equal to what the parser's own source string computes (evaluated with `new Function` in Node, where there is no CSP), for uniforms and for both buffer layouts. `allow_eval` is never used.
2. **`ModelInvalid` is a boot error.** `ModelInvalid { file, reason }` joins runtime's `BootError` (its owner) and ui's `BootFailure` (published: a patch changeset). The panel draws a new state, `model-invalid`, "A 3D model in this copy of the game is damaged: {file}." with Try again, which re-runs boot in a fresh scope and so fetches the file again (D3-f). `RendererFactory` may fail with `RendererUnavailable | ModelInvalid`. Reasons: `skinned`, `malformed: <what>`, `unsupported type`, `not loaded`.
3. **Models load before the Pixi app, through runtime `Assets`.** A `mesh(file)` view names its file; `createPixi3dRenderer` parses every named file from `target.assets` (already fetched with byte progress and the 30 s stall, M1.5) before it builds the app, so a bad model fails boot and nothing renders partly. A game lists its model files in `defineGame({ preload })`, which becomes `GameDefinition.preload`: boot adds them to the first preload screen's files, outside the content, so `content.hash` (which stamps saves) never depends on an origin or a hashed file name (review of #241; drafted as part of the default content).
4. **`defineGame({ createRenderer })`.** Core never imports an extension, so a game picks the 3D renderer with `createRenderer: (options) => createPixi3dRenderer({ ...options, views })`: core passes the Pixi options it built (size, pixel art, the draw layer's and Settings' `setup`) and the extension wraps them.
5. **D3-c, read as written for a lossless prop.** The `.bin` pack (The Last Light's `LLP1` layout, served as `.bin`, M3-D8) quantises positions, normals and UVs, so a real Meshy prop's pack differs from its GLB by design. D3-c is proven on a fixture prop whose values lie on the pack's grid: its `.glb` and `.bin` give byte-identical `Geometry3D` vertex buffers. The ported source test checks the real `desk.pack` against `desk.glb` (bounds and counts).
6. **Pose fields.** A 3D view reads `x`, `y`, `z` (metres) and `yaw` (radians about +y) from the component it is registered under, each interpolated by `alpha` (`yaw` by the shorter arc); missing fields are 0.
7. **Renderers.** `createPixi3dRenderer` refuses a stage whose renderer is not WebGL2 or WebGPU (Pixi's Canvas fallback, S7-Q1 Firefox) with `RendererUnavailable`.
8. **Context loss.** On `webglcontextlost` the renderer publishes `render.context.lost` and stops drawing; when the browser restores the context within `CONTEXT_RESTORE_MS` (5 s, an agent default: the spec names none), it publishes `render.context.restored` and draws again (Pixi and `@pixi/3d` re-upload their GPU resources). When it does not, or a WebGPU device is lost (`device.lost`; it never comes back), the renderer asks the runtime, through `RenderTarget.reportLost`, for the "picture stopped" panel (`context-lost`), whose Try again replaces the Pixi app, the View3D and the views in a fresh scope, resynced from the rows the sim last drew (review of #241). X-c's sim-hash check on `base-3d` stays with M3.10.
9. **Packaging (X-b, S7-g) in `ship`.** `prepareBuild` and `prepareItch` read the build's scripts and pages for `@pixi/3d` markers: `./extras` markers always fail (`Pixi3dExtrasInBuild`, a CSP violation under Ruken); core markers fail when the target is public (`Pixi3dInPublicBuild`, the D-1 reason). `prepare`, `publish` and itch.io are public; `deploy-dev` (the private dev host) and `publish --private` are private, and `publish --private` uploads only when `RUKEN_API` is Ruken's local stack (localhost, a `.localhost` name or loopback; `PrivatePublishNotLocal` otherwise). (Drafted as `prepare --private`; the review of #241 found that a private prepare followed by a raw `ruken publish` was a public upload with the guard off.) `ship` is published: a patch changeset.
10. **Examples.** `render3d` joins the core modules (M3R-D20, `Tier: core`); the catalog accepts `render-pixi3d`'s entries as an **unpublished extension** (D-1); the playground's public catalog leaves out any example that imports one, and `build:playground` leaves out the resources only such examples name (`examples/resources/models/`), so the website never ships the beta or The Last Light's models.
11. **`render-pixi` change is additive.** `RenderDeltaConsumer`, `EntityView`, `EntityViewFactory` and `EntityViewResolver` take a container type parameter defaulting to Pixi's `Container` (S7-Q5: `Container3D` is not a `Container`). `render-pixi` is private: no changeset; its API report is updated.

## Findings for the Owner

- **Review of #241 (2026-10-30), all addressed below:** publish --private replaces prepare --private; a context that does not come back shows the panel; `model-invalid` offers Back to the host; the parsers validate counts, indices and bufferViews; the renderer frees its models; the panel names the file's base name and wraps it; `preload` stays out of `content.hash`; the playground leaves the models out; context-loss and texture tests; optional: the renderer requires `render-pixi3d/no-eval`, `createRenderer` must be a function, the marker scan reads pages.
- **Try again inside a Ruken frame never re-handshakes.** `@ruken/sdk-host` answers one `hello` per frame load (it re-arms only on a reload, `outbox` `state === "connecting" || rearmed`), while `runGame`'s Try again re-runs boot in the same frame and sends a second `hello`, which is dropped, so the page stays `loading`. Seen with D3-f under the fake host; it holds for every boot failure, not only `ModelInvalid`. The D3-f journey runs standalone, where Try again works. Not fixed here (runtime and Ruken's contract; a Ruken request or a runtime change for its owner).
- **The `View3D` clears the whole canvas.** Inside the letterbox, the view's clear covers the bars and, in portrait, the backdrop under the field (the screenshot shows black where a 2D game shows the bars' colour), and `backgroundColor` has no effect. The look is the camera and lighting tasks' (M3.4b–d); recorded so they size or clip the view.
- **`@pixi/3d` 0.1.0-beta.2: render-to-texture reads back black in macOS Firefox.** On the Mac runner's Firefox, rendering the stage into a `RenderTexture` and reading it with `extract.pixels` returns all black while the canvas holds the scene (probe branch `claude/3d-m3-4a-ff-probe` @ `1ca28222`, dispatch run 41052001604: the canvas read has the box and mesh, the texture read is one colour). It failed 5 of 7 cases in `renderer.parity.test.ts` there. The parity helper now reads the canvas with `gl.readPixels` in the task of the draw; the renderer itself never renders to a texture today. Shadows and post effects (M3.4d, M9.10) render to textures, so they must be checked in macOS Firefox before they ship. The probe branch is the Owner's to delete.
- **Playwright WebKit screenshots of a WebGL canvas are black here.** The WebKit journey reads the canvas in an animation frame (its capture shows the box and both nightstands); `page.screenshot` in WebKit cannot be used as visual evidence for 3D.
- **The example's light is the sky-and-ground fill only** (no directional light: `@pixi/3d` is not a public example import), so the nightstands read dark. Lamps arrive with M3.4d.
