## How the work runs

Stages, each its own fresh session and branch, no subagents, handoff by committed documents, refresh after 90 minutes:
spec (coordinator with the Owner), plan (`claude-fable-5-2`, medium), plan audit (`claude-opus-5-5`, medium), execution
(`claude-sonnet-5-5`, high), implementation audit (Opus, medium), fixes (Sonnet, high), the Owner's review.

Rules learned the hard way:

- A session knows only its brief. Tell it to call ReadNotifications after every step and to report with `send_message`.
  Some sessions finish without their report arriving: if one goes idle, read its branch and its audit README.
- A session refuses work its own brief forbade, even when the coordinator later messages a go-ahead. Start a new session
  whose brief includes the change.
- The Owner sometimes writes to a child session directly. Check its transcript (`list_events`, kind `user`) before
  overruling what it says he said.
- Code branches carry no tracker edits. Rows go in each branch's audit README under "For the tracker"; gather them in a
  docs branch.
- A branch needs a real merge of main, not a copy of main's tracker.
- Nothing visual goes to the Owner until the coordinator has opened it. Figures are judged at density 2 only.
- The merge session pushes nothing and resolves no conflicts; it gates exact merge trees, opens pull requests and merges.
